# Команды с косой чертой

Команды с косой чертой — это встроенные управляющие команды MultiAI CLI в интерактивном TUI. Они позволяют настраивать учётную запись, управлять сеансами, переключать режимы, просматривать информацию и выполнять другие действия. Введи `/` в поле ввода, чтобы открыть автодополнение: список вариантов фильтруется по мере ввода и учитывает псевдонимы команд.

После полного имени команды нажми `Enter`. Если ввод с префиксом `/` не совпадает ни с одной встроенной командой или командой Skill, он отправляется агенту как обычное сообщение.

::: tip Совет
Некоторые команды доступны только во время простоя. Если сеанс выводит потоковый ответ или сжимает контекст, такие команды будут заблокированы — сначала нажми `Esc` или `Ctrl-C`, чтобы прервать операцию. Столбец «Всегда доступна» в таблицах ниже показывает, можно ли использовать команду во время потокового вывода.
:::

| `/account` | `/profile` | Показать профиль MultiAI, кошелёк, квоты подписки, сведения о подключении, замаскированные ключи API и использование ресурсов в текущем сеансе | Нет |
| `/provider` | — | Открыть интерактивный менеджер провайдеров для просмотра, добавления и удаления настроенных провайдеров. См. [Платформы и модели — `/provider` и управление провайдерами](../configuration/providers.md#provider-与供应商管理) | Да |
| `/model` | — | Сменить LLM-модель текущего сеанса | Да |

| `/settings` | `/config` | Открыть панель настроек в TUI | Да |

| `/permission` | — | Выбрать режим разрешений | Да |
| `/editor` | — | Настроить внешний редактор, запускаемый сочетанием `Ctrl-G` | Да |

## Управление сеансами

| Команда | Псевдоним | Описание | Всегда доступна |
| --- | --- | --- | --- |
| `/new` | `/clear` | Начать новый сеанс, сбросив текущий контекст | Нет |
| `/sessions` | `/resume` | Просмотреть историю сеансов и переключиться на нужный сеанс или восстановить его | Нет |
| `/tasks` | `/task` | Просмотреть список фоновых задач | Да |
| `/fork` | — | Создать ответвлённый сеанс с полной историей текущего диалога | Нет |
| `/title [<text>]` | `/rename` | Без аргументов показать заголовок текущего сеанса; с аргументом задать новый заголовок (не более 200 символов) | Да |
| `/compact [<instruction>]` | — | Сжать контекст текущего диалога, чтобы освободить токены; необязательная инструкция подсказывает модели, что нужно сохранить | Нет |
| `/undo [<count>]` | — | Отменить последние запросы в активном контексте. Без числа открывает список выбора, с числом отменяет указанное количество запросов. Запросы до последнего сжатия отменить нельзя. Вместе с ними откатываются список задач и состояние Plan mode, но изменения кода не отменяются | Нет |
| `/reload` | — | Перезагрузить текущий сеанс и применить свежие настройки `config.toml` (провайдеры, модели и т. д.) и параметры интерфейса из `tui.toml`, не перезапуская CLI | Нет |
| `/reload-tui` | — | Перезагрузить только параметры интерфейса из `tui.toml` (тему, редактор, уведомления и т. д.), не пересоздавая сеанс | Да |
| `/init` | — | Проанализировать текущую кодовую базу и создать `AGENTS.md` | Нет |
| `/export-md [<path>]` | `/export` | Экспортировать текущий сеанс в файл Markdown | Нет |
| `/export-debug-zip` | — | Экспортировать текущий сеанс в отладочный ZIP-архив (аналог [`multiai export`](./multiai-command.md#multiai-export)) | Нет |
| `/copy` | — | Скопировать последнее сообщение ассистента в буфер обмена | Нет |
| `/add-dir [<path>]` | — | Добавить в текущий сеанс дополнительный рабочий каталог. Запуск без пути (или с `list`) выводит список настроенных каталогов. При добавлении можно сохранить каталог для проекта в `.multiai/local.toml` | Нет |
| `/web` | — | Открыть текущий сеанс в веб-интерфейсе: выбрать запущенный сервер или запустить новый сервер на переднем плане после выхода из TUI. См. [`multiai web`](./multiai-command.md#multiai-web) | Да |

## Режимы и управление выполнением

| Команда | Псевдоним | Описание | Всегда доступна |
| --- | --- | --- | --- |
| `/yolo [on\|off]` | `/yes` | Переключить YOLO mode. Без аргументов меняет текущее состояние, а `on`/`off` задаёт его явно. Во включённом состоянии пропускает подтверждение обычных вызовов инструментов; подтверждение выхода из Plan mode не затрагивается | Да |
| `/auto [on\|off]` | — | Переключить автоматический режим разрешений. Во включённом состоянии подтверждения инструментов обрабатываются автоматически, а агент не задаёт пользователю вопросов | Да |
| `/plan [on\|off]` | — | Переключить Plan mode. Без аргументов меняет текущее состояние, а `on`/`off` задаёт его явно. Простое переключение не создаёт пустой файл плана | Да |
| `/plan clear` | — | Очистить текущий план | Нет |
| `/swarm on\|off` | — | Включить или выключить режим роя, не отправляя запрос | Да |
| `/swarm <task>` | — | Включить режим роя и отправить `<task>` как обычный запрос. После нормального завершения хода режим автоматически выключится. В режиме разрешений `manual` MultiAI CLI перед запуском предложит перейти в `auto` или `yolo` | Нет |
| `/goal [...]` | — | Запустить автономную цель или управлять ею | См. ниже |

::: warning Внимание
`/yolo` пропускает подтверждение обычных вызовов инструментов. Перед включением убедись, что понимаешь возможные риски. `/yolo` не отменяет подтверждение выхода из Plan mode; на `Bash` внутри Plan mode по-прежнему действуют обычные правила разрешений `/yolo`.
:::

## Автономная цель

`/goal` запускает режим цели или управляет им. Цель — это постоянная задача, к которой MultiAI CLI движется на протяжении автоматически продолжающихся ходов. Рекомендации и примеры см. в разделе [Цели](../guides/goals.md).

```sh
/goal Обнови документацию по оформлению заказа, запусти сборку документации и остановись, если задача всё ещё заблокирована через 20 ходов
```

| Команда | Действие | Доступность |
| --- | --- | --- |
| `/goal` или `/goal status` | Показать текущую цель, её состояние, прошедшее время, количество ходов и токенов | Всегда |
| `/goal pause` | Приостановить активную цель, сохранив её | Всегда |
| `/goal resume` | Продолжить приостановленную или заблокированную цель | Только во время простоя |
| `/goal cancel` | Удалить текущую цель | Всегда |
| `/goal replace <objective>` | Заменить сохранённую цель новой | Только во время простоя |
| `/goal next <objective>` | Поставить следующую цель в очередь этого сеанса. Если активной цели нет, запустить её сразу. Агент не видит цели в очереди до завершения текущей | Всегда |
| `/goal next manage` | Открыть менеджер следующих целей. Используй <kbd>↑</kbd> / <kbd>↓</kbd> для навигации, <kbd>Space</kbd> для выбора перемещаемой цели, затем <kbd>↑</kbd> / <kbd>↓</kbd> для изменения порядка, <kbd>E</kbd> для редактирования, <kbd>D</kbd> для удаления и <kbd>Esc</kbd> для отмены. В поле редактирования <kbd>Shift-Enter</kbd> или <kbd>Ctrl-J</kbd> добавляет новую строку, а <kbd>Enter</kbd> сохраняет изменения | Всегда |

Слова `status`, `pause`, `resume`, `cancel`, `replace` и `next` работают как подкоманды, только если стоят первыми после `/goal`. Если цель должна начинаться с одного из них, поставь перед текстом `--`:

```sh
/goal -- cancel старую заметку о развёртывании после публикации новой документации
```

Если следующая цель должна начинаться со слова `manage`, поставь `--` после `next`:

```sh
/goal next -- manage контрольный список релиза
```

В неинтерактивном режиме запросов режим цели запускают только формы создания:

```sh
multiai -p "/goal Исправь падающий тест оформления заказа"
```

Режим запросов завершается с кодом `0`, если цель выполнена, `3`, если она заблокирована, и `6`, если она приостановлена. Остальные подкоманды `/goal`, включая `next`, являются элементами управления TUI и не обрабатываются командой `multiai -p`.

## Встроенные команды Skill

В MultiAI CLI входит набор встроенных Skills, которые доступны напрямую как команды `/<name>`. В отличие от внешних Skills, им не нужен префикс `skill:`, и они работают сразу после установки.

| Команда | Описание |
| --- | --- |
| `/mcp-config` | Настроить MCP-серверы и выполнить вход через MCP OAuth. См. [MCP](../customization/mcp.md) |
| `/custom-theme [<text>]` | Создать или изменить пользовательскую цветовую тему TUI. См. [Темы](../customization/themes.md) |
| `/update-config` | Просмотреть или изменить `config.toml` (модель, провайдер, разрешения, хуки) и `tui.toml` (тема, редактор, уведомления, автообновление) |
| `/check-multiai-docs` | Ответить на вопросы о MultiAI CLI по документации проекта |
| `/import-from-cc-codex` | Импортировать инструкции, Skills и настройки MCP из Claude Code и Codex в MultiAI CLI |
| `/sub-skill` | Найти локальные Skills и реорганизовать их в иерархические наборы суб-Skills. Включает `/sub-skill.review` (предложение без изменений) и `/sub-skill.consolidate` (применение реорганизации) |

Все встроенные команды Skill доступны только во время простоя.

## Динамические команды Skill

Активированные внешние Skills автоматически регистрируются как команды с косой чертой. Обычные внешние Skills используют пространство имён `skill:`:

```
/skill:<name> [дополнительный текст]
```

Например, `/skill:code-style` загружает Skill с именем `code-style` и отправляет его агенту; текст после команды добавляется к запросу Skill.

Внешние суб-Skills отображаются прямо в панели команд с составными именами через точку:

```
/<parent-skill>.<sub-skill> [дополнительный текст]
```

Например, дочерний Skill `review` внутри родительского Skill `code-style` отображается как `/code-style.review`. Составное имя команды формируется из иерархии; в дочернем `SKILL.md` можно оставить локальное значение `name`.

Для удобства внешние команды Skill также поддерживают сокращённую форму без префикса `skill:` — `/<name>`, если это имя не занято системной командой. Иными словами, `/code-style` при необходимости сопоставляется с `/skill:code-style`.

Встроенные Skills из MultiAI CLI отображаются в панели напрямую как `/<name>`. Например, `/mcp-config` помогает настроить MCP-серверы и вход через MCP OAuth, а `/custom-theme [дополнительный текст]` запускает процесс создания или изменения темы TUI.

::: info Примечание
Все команды Skill доступны только во время простоя. Skills типа `flow` также вызываются через `/skill:<name>` — отдельного пространства имён `/flow:` нет.
:::

Сведения об установке и создании Skills см. в разделе [Agent Skills](../customization/skills.md).
