# Встроенные инструменты

Встроенные инструменты — это набор инструментов, который MultiAI CLI предоставляет вместе со своим основным движком; устанавливать MCP-сервер не требуется. Во время каждого разговора агент автоматически выбирает и вызывает подходящие для текущей задачи инструменты, а пользователи могут просмотреть сведения о каждом вызове через интерфейс подтверждения.

В отличие от MCP-инструментов, встроенные инструменты управляются непосредственно средой выполнения, их жизненный цикл привязан к сеансу, а внешний процесс не требуется. Для обоих типов действует единый механизм подтверждений: **инструменты только для чтения** (например, `Read`, `Grep`, `Glob`) по умолчанию разрешены автоматически, а **инструменты записи и выполнения** (например, `Write`, `Edit`, `Bash`) по умолчанию требуют подтверждения пользователя. В YOLO mode подтверждение обычных вызовов инструментов пропускается; подтверждение выхода из Plan mode работает как прежде.

## Файловые инструменты

Файловые инструменты отвечают за чтение, запись и поиск в локальной файловой системе — это основа задач анализа и изменения кода.

| Инструмент | Подтверждение по умолчанию | Описание |
| --- | --- | --- |
| `Read` | Разрешать автоматически | Прочитать содержимое текстового файла |
| `Write` | Требует подтверждения | Создать или перезаписать файл |
| `Edit` | Требует подтверждения | Выполнить точную замену строки |
| `Grep` | Разрешать автоматически | Полнотекстовый поиск на базе ripgrep |
| `Glob` | Разрешать автоматически | Найти файлы по glob-шаблону |
| `ReadMediaFile` | Разрешать автоматически | Прочитать файл изображения или видео |

**`Read`** принимает путь к файлу (`path`), а также необязательные параметры `line_offset` (номер начальной строки; отрицательные значения отсчитываются от конца) и `n_lines` (максимальное число читаемых строк). Один вызов возвращает не более 1000 строк или 100 КБ; если содержимое превышает этот предел, к результату добавляется уведомление об усечении. Если файл является изображением или видео, инструмент предлагает вместо этого использовать `ReadMediaFile`.

**`Write`** принимает `path`, `content` и необязательный `mode` (`overwrite` или `append`; по умолчанию — перезапись). Отсутствующие родительские каталоги создаются автоматически; режим `append` добавляет содержимое в конец файла, не вставляя автоматически перевод строки.

**`Edit`** принимает `path`, `old_string` (точный заменяемый текст) и `new_string` (новый текст). По умолчанию заменяется только одно уникальное совпадение; если одинаковое содержимое встречается в файле несколько раз, инструмент возвращает ошибку и предлагает использовать `replace_all: true`. Значения `old_string` и `new_string` не должны совпадать.

**`Grep`** вызывает ripgrep для поиска по содержимому файлов и поддерживает регулярные выражения (`pattern`), путь поиска (`path`), фильтрацию по типу файла (`type`, например `ts`, `py`), glob-фильтр (`glob`) и режим вывода (`output_mode`: `files_with_matches` / `content` / `count_matches`; по умолчанию — `files_with_matches`). В режиме `content` поддерживаются строки контекста (`-A`, `-B`, `-C`), поиск без учёта регистра (`-i`), номера строк (`-n`, по умолчанию включены) и многострочный поиск (`multiline`). Во всех режимах доступна пагинация `offset` + `head_limit`; по умолчанию `head_limit` равен 250, а `0` снимает ограничение. Конфиденциальные файлы, например `.env` и закрытые ключи, автоматически исключаются. Чтобы искать в файлах, игнорируемых `.gitignore`, задайте `include_ignored=true`; конфиденциальные файлы всё равно останутся исключёнными.

**`Glob`** сопоставляет файлы в указанном каталоге (`path`; по умолчанию — рабочий каталог) с glob-шаблоном (`pattern`). Результаты сортируются по времени изменения в убывающем порядке и ограничены 100 записями. По умолчанию учитываются `.gitignore`, `.ignore` и `.rgignore`; задайте `include_ignored=true`, чтобы включить игнорируемые файлы, например результаты сборки, при этом конфиденциальные файлы всё равно будут исключены. Поддерживаются шаблоны со скобками, например `*.{ts,tsx}`, и широкие шаблоны с подстановочными знаками, однако они обычно усекаются при достижении лимита совпадений.

**`ReadMediaFile`** отправляет изображение или видео модели как мультимодальное содержимое. Инструмент принимает `path`, а также необязательные параметры детализации изображения, например `region` и `full_resolution`; максимальный размер файла — 100 МБ. При обычном чтении изображения сжимаются до ограничений настроенной модели. Если автоматическое сжатие не может безопасно уложиться в эти ограничения, инструмент возвращает ошибку, не отправляя исходное изображение, и предлагает модели создать и прочитать уменьшенную копию. Доступность зависит от возможностей текущей модели по обработке изображений и видео (`image_in` / `video_in`).

## Оболочка

| Инструмент | Подтверждение по умолчанию | Описание |
| --- | --- | --- |
| `Bash` | Требует подтверждения | Выполнить команду оболочки |

**`Bash`** — самый требовательный к разрешениям и одновременно самый универсальный инструмент. Параметры:

- `command` (обязательный): команда оболочки для выполнения
- `cwd`: рабочий каталог
- `timeout`: тайм-аут в миллисекундах; по умолчанию для выполнения на переднем плане — 60 секунд, максимум — 5 минут
- `run_in_background`: выполнять ли как фоновую задачу; тайм-аут фоновых задач по умолчанию — 10 минут (в режиме печати `multiai -p` по умолчанию тайм-аута нет)
- `description`: описание фоновой задачи; обязательно при `run_in_background=true`
- `disable_timeout`: снять ли ограничение тайм-аута для фоновых задач

Режим переднего плана блокирует текущий ход до завершения команды или истечения тайм-аута, а TUI передаёт stdout и stderr в карточку выполняющегося инструмента `Bash`, пока команда активна. По умолчанию команда переднего плана, достигшая тайм-аута, не завершается принудительно — она продолжает выполняться как фоновая задача (с ограничением стандартного фонового тайм-аута 600 секунд). Чтобы вернуть принудительное завершение по тайм-ауту, задайте [`bash_auto_background_on_timeout`](../configuration/config-files.md#background) значение `false` в разделе `[background]`. Стандартные 600 секунд можно настроить через [`bash_task_timeout_s`](../configuration/config-files.md#background) (`0` = без тайм-аута); в режиме печати (`multiai -p`) тайм-аут по умолчанию отсутствует. Фоновый режим сразу возвращает ID задачи и автоматически уведомляет агента о её завершении. stdin всегда закрыт — интерактивные команды сразу получают EOF. Двухэтапное завершение (SIGTERM → 5 секунд ожидания → SIGKILL) обеспечивает надёжную очистку процессов при остановке задачи или достижении фонового тайм-аута. В Windows по умолчанию используется Git Bash.

## Веб-инструменты

| Инструмент | Подтверждение по умолчанию | Описание |
| --- | --- | --- |
| `WebSearch` | Разрешать автоматически | Поиск в интернете |
| `FetchURL` | Разрешать автоматически | Получить содержимое указанного URL |

**`WebSearch`** принимает `query` (поисковый запрос). Хост должен предоставлять реализацию поиска; если она не внедрена, инструмент не отображается в списке.

**`FetchURL`** принимает единственный параметр `url` и возвращает содержимое страницы. Для HTML-страниц хост извлекает текст body вместо полного HTML; простой текст и Markdown передаются без изменений. Также требует реализации со стороны хоста.

## Plan mode

| Инструмент | Подтверждение по умолчанию | Описание |
| --- | --- | --- |
| `EnterPlanMode` | Разрешать автоматически | Войти в Plan mode |
| `ExitPlanMode` | Разрешать автоматически (пользователь должен подтвердить план) | Выйти из Plan mode и отправить план |

Plan mode — ограниченное рабочее состояние: после входа `Write` и `Edit` могут записывать только текущий файл плана, а `TaskStop` полностью блокируется. Все остальные инструменты (включая `Bash`) по-прежнему подчиняются текущим правилам разрешений.

**`EnterPlanMode`** не принимает параметров; при успешном выполнении возвращает рекомендации по процессу и путь к файлу плана.

**`ExitPlanMode`** читает текущий файл плана, показывает план пользователю для подтверждения, а затем выходит из Plan mode. Необязательный параметр `options` позволяет агенту предложить 1–3 альтернативных подхода (каждый с `label` и `description`; максимальная длина `label` — 80 символов), из которых пользователь выбирает при подтверждении. Метки должны быть уникальными и не могут содержать зарезервированные слова `Approve`, `Reject`, `Reject and Exit` или `Revise`.

## Управление состоянием

| Инструмент | Подтверждение по умолчанию | Описание |
| --- | --- | --- |
| `TodoList` | Разрешать автоматически | Управлять списком задач |

**`TodoList`** сохраняет видимый список подзадач при многоэтапных операциях; состояние хранится в сеансе агента. Параметр `todos` принимает массив, где у каждого элемента есть `title` и `status` (`pending` / `in_progress` / `done`). Если `todos` не указан, возвращается текущий список; пустой массив очищает его.

## Инструменты совместной работы

Инструменты совместной работы отвечают за координацию агентов, взаимодействие с пользователем и вызов Skill.

| Инструмент | Подтверждение по умолчанию | Описание |
| --- | --- | --- |
| `Agent` | Разрешать автоматически | Запустить субагента для выполнения подзадачи |
| `AgentSwarm` | Разрешать автоматически в режиме роя; в остальных случаях требует подтверждения | Запустить субагентов по элементам или возобновить существующих субагентов |
| `AskUserQuestion` | Разрешать автоматически | Задать пользователю вопрос для получения структурированного ответа |
| `Skill` | Разрешать автоматически | Вызвать зарегистрированный встраиваемый Skill |

**`Agent`** делегирует подзадачу субагенту. Обязательные параметры: `prompt` (полное описание задачи) и `description` (краткое описание из 3–5 слов). Необязательные параметры: `subagent_type` (по умолчанию `coder`), `resume` (ID существующего агента для возобновления; несовместим с `subagent_type`), `run_in_background` (по умолчанию false) и `model` (`"secondary"` для вторичной модели из `[secondary_model] model` или `"primary"` для основной модели; игнорируется при возобновлении; доступен при включённом эксперименте со вторичной моделью в `multiai web` или экспериментальном `multiai -p`, но не в TUI). Явный `model` переопределяет `model_preference` выбранного [профиля агента](../customization/agents.md#agent-file-format); если не задано ни то ни другое, по умолчанию используется настроенная вторичная модель, а при её отсутствии субагент наследует модель вызывающего агента. По умолчанию задачи агентов завершаются по тайм-ауту через 2 часа; лимит настраивается через `[subagent] timeout_ms` в `config.toml` (`0` = без тайм-аута, также доступна переменная окружения `MULTIAI_SUBAGENT_TIMEOUT_MS`), а в режиме печати (`multiai -p`) тайм-аут по умолчанию отсутствует. На переднем плане родительский агент ждёт завершения субагента; в фоне сразу возвращается ID задачи, а итог после завершения автоматически доставляется основному агенту синтетическим сообщением User. Если на одном шаге выполняется несколько вызовов `Agent` на переднем плане, TUI объединяет их и показывает для каждого субагента состояние выполнения, ожидания, завершения или ошибки и прошедшее время. Подробнее см. [Агент и субагенты](../customization/agents.md).

**`AgentSwarm`** запускает субагентов из общего `prompt_template` и массива `items`, возобновляет существующих субагентов через `resume_agent_ids` либо совмещает оба действия в одном вызове. Шаблон должен содержать заполнитель `{{item}}`; каждый элемент заменяет его и запускает нового субагента. Параметр `subagent_type` выбирает профиль всех запускаемых субагентов; если его не указать, используется `coder`. Параметр `model` доступен при включённом эксперименте со вторичной моделью в `multiai web` или экспериментальном `multiai -p`, но не в TUI; он запускает создаваемых из элементов субагентов на вторичной модели из `[secondary_model] model` (`"secondary"`) или основной модели (`"primary"`). Этот явный выбор переопределяет `model_preference` выбранного [профиля агента](../customization/agents.md#agent-file-format); если не задано ни то ни другое, по умолчанию используется настроенная вторичная модель, а при её отсутствии субагент наследует модель вызывающего агента. Возобновляемые субагенты сохраняют собственные модели. Без `resume_agent_ids` требуется не менее 2 элементов; с `resume_agent_ids` можно возобновить одного или нескольких существующих субагентов. Инструмент поддерживает до 128 субагентов, ждёт завершения всех и возвращает сводный отчёт. В TUI рои на переднем плане показывают над полем ввода панель прогресса `Agent swarm`. Если ответ модели вызывает `AgentSwarm`, этот вызов должен быть единственным вызовом инструмента в ответе. Для нескольких роёв вызывайте их по очереди либо объедините работу в один рой, если подходит общий шаблон. В режиме разрешений `manual` вызовы вне активного режима роя требуют подтверждения, если их не разрешает правило; при активном режиме роя сам `AgentSwarm` подтверждается автоматически. Правила сопоставляют только имя `AgentSwarm`; шаблоны аргументов вроде `AgentSwarm(swarm)` не поддерживаются. По умолчанию параллелизм постепенно увеличивается без верхнего предела: сначала запускаются 5 субагентов, затем ещё по 5 каждые 2 секунды. Начальный предел можно задать переменной окружения `MULTIAI_AGENT_SWARM_MAX_CONCURRENCY`.

**`AskUserQuestion`** задаёт пользователю структурированный вопрос с вариантами ответа — это полезно для устранения неоднозначности или выбора варианта. Параметр `questions` принимает 1–4 вопроса; для каждого обязательны `question` (заканчивается на `?`) и `options` (2–4 варианта с `label` и `description`), а также доступны необязательные `header` (до 12 символов) и `multi_select` (по умолчанию false). Вариант «Другое» добавляется автоматически. Значение `background=true` запускает фоновую задачу вопроса и сразу возвращает её ID. Если хост не поддерживает интерактивные вопросы, возвращается сообщение об ошибке, после чего агенту следует задать вопрос непосредственно в текстовом ответе.

**`Skill`** позволяет агенту явно вызвать зарегистрированный Skill типа inline. Принимает `skill` (имя Skill) и необязательный `args` (дополнительный текст аргументов). Через этот инструмент можно вызывать только Skill с `type = "inline"`; Skill с `disableModelInvocation: true` отклоняются. Максимальная глубина вложенности — 3 уровня. Подробнее см. [Agent Skills](../customization/skills.md).

## Фоновые задачи

Инструменты фоновых задач управляют задачами, запущенными через `Bash`, `Agent` или `AskUserQuestion`. Когда задача достигает конечного состояния, её статус и путь к сохранённому выводу автоматически передаются агенту; для досрочной проверки хода выполнения используйте `TaskOutput`.

| Инструмент | Подтверждение по умолчанию | Описание |
| --- | --- | --- |
| `TaskList` | Разрешать автоматически | Показать фоновые задачи |
| `TaskOutput` | Разрешать автоматически | Просмотреть вывод фоновой задачи |
| `TaskStop` | Требует подтверждения | Остановить выполняющуюся фоновую задачу |

**`TaskList`** возвращает список фоновых задач. Необязательные параметры: `active_only` (по умолчанию true; показывать только выполняющиеся задачи) и `limit` (по умолчанию 20; диапазон 1–100).

**`TaskOutput`** возвращает статус и вывод задачи по её `task_id`. Встроенный предпросмотр содержит не более последних 32 КБ; полный журнал сохраняется на диск, а инструмент также возвращает `output_path` и предлагает использовать `Read` для постраничного чтения. Необязательные параметры `block` (по умолчанию false) и `timeout` (ожидание в секундах; по умолчанию 30; диапазон 0–3600) позволяют перед возвратом дождаться завершения задачи.

**`TaskStop`** принимает `task_id` и необязательный `reason` (по умолчанию `Stopped by TaskStop`). Его безопасно вызывать и для задач, уже находящихся в конечном состоянии.

## Запланированные задачи

Инструменты запланированных задач позволяют агенту в будущем повторно внедрить запрос в текущий сеанс — однократно как напоминание или периодически по cron-расписанию (проверки, ежедневные отчёты, мониторинг развёртывания и т. п.). Расписания привязаны к сеансу и сохраняются при его возобновлении через `multiai --session`, но не переносятся в совершенно новый сеанс. В одном сеансе может быть не более 50 активных запланированных задач. Чтобы полностью отключить их, задайте `MULTIAI_DISABLE_CRON=1`; см. [Переменные окружения](../configuration/env-vars.md#运行时开关).

| Инструмент | Подтверждение по умолчанию | Описание |
| --- | --- | --- |
| `CronCreate` | Требует подтверждения | Запланировать запуск запроса в будущем |
| `CronList` | Разрешать автоматически | Показать запланированные задачи |
| `CronDelete` | Требует подтверждения | Отменить запланированную задачу |

**`CronCreate`** принимает `cron` (стандартное cron-выражение из 5 полей в локальном часовом поясе пользователя: `minute hour day-of-month month day-of-week`), `prompt` (внедряемый при срабатывании текст; лимит UTF-8 — 8 КБ) и необязательный `recurring` (по умолчанию `true`; передайте `false` для однократного напоминания, которое удаляется после срабатывания). При успехе возвращаются 8-значный шестнадцатеричный `id`, понятное человеку `humanSchedule` (например, `every 5 minutes`) и `nextFireAt` (ISO-метка времени следующего запуска).

Чтобы все пользователи не запускали задачи одновременно в начале часа, планировщик применяет детерминированный джиттер: периодические задачи сдвигаются вперёд на `min(10% of the period, 15 minutes)`, а однократные задачи ровно на `:00` или `:30` — не более чем на 90 секунд. Если планировщик пропустил несколько запусков (например, ноутбук спал), после пробуждения задача выполняется только один раз; запрос оборачивается в `<cron-fire>` с `coalescedCount`. Периодические задачи старше 7 дней срабатывают в последний раз с `stale="true"`, после чего автоматически удаляются; чтобы продолжить их выполнение, снова вызовите `CronCreate`.

**`CronList`** — инструмент только для чтения без параметров. Он возвращает по одной записи для каждой активной задачи с полями `id`, `cron`, `humanSchedule`, `nextFireAt`, `recurring`, `ageDays` и `stale`. Записи разделяются `---` и сортируются по времени расписания.

**`CronDelete`** принимает один `id`. Для периодических задач немедленно прекращаются все будущие запуски; для однократных отменяется ожидающий запуск. Уже сработавшие однократные задачи удаляются автоматически, поэтому вызов `CronDelete` для такой задачи возвращает `No cron job with id ...`. Удаление необратимо — для восстановления снова используйте `CronCreate`. В Plan mode `CronDelete` также заблокирован.
