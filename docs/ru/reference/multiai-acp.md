# Подкоманда `multiai acp`

`multiai acp` переключает MultiAI CLI в режим **ACP (Agent Client Protocol)**: программа обменивается с клиентом ACP (например, Zed или JetBrains AI Chat) сообщениями JSON-RPC через stdin/stdout, благодаря чему IDE может напрямую управлять сеансами, запросами и вызовами инструментов MultiAI CLI.

```sh
multiai acp
```

После запуска команда не выводит баннер и сразу ожидает от клиента ACP запрос `initialize` в stdin. Журналы записываются в stderr (а также в диагностический журнал в `~/.multiai/logs/`), поэтому сам канал ACP остаётся чистым.

::: tip Кто вызывает эту команду?
Обычно запускать `multiai acp` вручную не нужно — эта команда служит точкой входа в подпроцесс для IDE. Настройка со стороны IDE описана в разделе [«Использование в IDE»](../guides/ides.md).
:::

## Матрица возможностей

В таблице перечислены возможности, объявляемые текущим слоем адаптера ACP. Поле `agentCapabilities` полностью возвращается в ответе `initialize`, чтобы IDE могла соответствующим образом настроить интерфейс.

| Возможность | Значение | Описание |
| --- | --- | --- |
| `promptCapabilities.image` | `true` | Поддерживаются блоки содержимого ACP `image` (base64 + mimeType) |
| `promptCapabilities.audio` | `false` | Звуковые запросы пока не поддерживаются |
| `promptCapabilities.embeddedContext` | `true` | Клиент может отправлять встроенные блоки ресурсов `resource`/`resource_link`; текст добавляется в запрос как `<resource uri="...">...</resource>`, а двоичные ресурсы отбрасываются с предупреждением |
| `mcpCapabilities.http` | `true` | Перенаправляет HTTP-сервисы MCP, настроенные в IDE |
| `mcpCapabilities.sse` | `true` | Перенаправляет устаревшие SSE-сервисы MCP, настроенные в IDE |
| `loadSession` | `true` | Поддерживает `session/load` для продолжения существующего сеанса с воспроизведением истории |
| `sessionCapabilities.list` | `{}` | Поддерживает `session/list` для перечисления сеансов текущего пользователя |

## Поддержка методов ACP

Спецификация разделяет методы на **стабильный** и развивающийся **нестабильный** интерфейсы (обработчики с префиксом `unstable_*` в `@agentclientprotocol/sdk@0.23.0`). У них совершенно разные гарантии стабильности: стабильный интерфейс охватывает методы, используемые каждым рабочим клиентом ACP, а нестабильный — экспериментальные расширения (предсказание встроенных правок, синхронизацию буфера документа, управление провайдерами, запрос данных и т. д.), поэтому они учитываются отдельно.

**Итого: стабильная сторона агента — 10/12 (83%), обратный RPC клиента — 4/9 (44%); в нестабильном интерфейсе реализован только `session/set_model` (1/19).** Реализованы все методы, необходимые для обычного сценария агента (инициализация → аутентификация → создание/загрузка/продолжение → запрос → отмена + файловый ввод-вывод + подтверждение инструментов).

### Стабильная сторона агента — IDE → агент (10 / 12)

| Метод | Реализован | Описание |
| --- | --- | --- |
| `initialize` | Да | Согласование версии; возвращает `agentInfo: { name: 'MultiAI CLI', version }`, матрицу возможностей и `authMethods` |
| `authenticate` | Да | Проверяет `method_id='login'`; возвращает `authRequired (-32000)`, если токен отсутствует, и `invalidParams (-32602)` для неизвестного идентификатора |
| `session/new` | Да | Принимает `cwd` / `mcpServers`; возвращает `configOptions[]` |
| `session/load` | Да | Восстанавливает сеанс с диска и воспроизводит историю через `session/update` |
| `session/resume` | Да | Облегчённый аналог `session/load`; не воспроизводит историю |
| `session/prompt` | Да | Принимает блоки содержимого `text` / `image` / `resource` / `resource_link`; передаёт поток `agent_message_chunk` |
| `session/cancel` | Да | Прерывает текущий ход |
| `session/list` | Да | Перечисляет сеансы на диске (объявляется через `sessionCapabilities.list = {}`) |
| `session/set_mode` | Да | Совместимый путь; передаёт управление тому же обработчику, что и `set_config_option({configId:'mode'})` |
| `session/set_config_option` | Да | Единый диспетчер выбора модели, Thinking mode и режима |
| `session/close` | Нет | |
| `logout` | Нет | |

### Стабильный обратный RPC клиента — агент → IDE (4 / 9)

| Метод | Реализован | Описание |
| --- | --- | --- |
| `session/update` | Да | Передаёт поток `agent_message_chunk` / `tool_call*` / `plan` / `config_option_update` / `available_commands_update` |
| `session/request_permission` | Да | Общий канал для подтверждения инструментов и запроса данных у пользователя |
| `fs/read_text_file` | Да | Чтение файлов на уровне kaos перенаправляется клиенту (объявляется через `fsCapabilities`) |
| `fs/write_text_file` | Да | Запись файлов на уровне kaos перенаправляется клиенту |
| `terminal/create` · `output` · `release` · `kill` · `wait_for_exit` | Нет | Обратный RPC терминала не подключён; команды оболочки выполняются локально |

### Нестабильный интерфейс (1 / 19)

| Метод | Реализован | Описание |
| --- | --- | --- |
| `session/set_model` | Да | Совместимый путь; эквивалентен `set_config_option({configId:'model'})` |
| Остальные 18 методов | Нет | Включают расширения жизненного цикла сеанса, синхронизацию буфера, предсказание встроенных правок, управление провайдерами и т. д. |

Все не перечисленные выше методы возвращают `methodNotFound`.

## Перенаправление MCP

Когда клиент ACP передаёт `mcpServers` в `session/new` или `session/load`, слой адаптера выполняет следующие преобразования:

- `http` → конфигурация MultiAI CLI `transport: 'http'`
- `stdio` → конфигурация MultiAI CLI `transport: 'stdio'`
- `sse` → конфигурация MultiAI CLI `transport: 'sse'`
- `acp` → отбрасывается с записью предупреждения в журнал
