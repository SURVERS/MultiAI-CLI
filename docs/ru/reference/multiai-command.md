# Команда `multiai`

`multiai` — основная команда MultiAI CLI для запуска интерактивного сеанса в терминале. Без аргументов она открывает новый сеанс в текущем рабочем каталоге; с флагами можно продолжить предыдущий сеанс, пропустить подтверждения, запустить Plan mode или загрузить Skills из пользовательского каталога.

```sh
multiai [options]
multiai <subcommand> [options]
```

## Параметры основной команды

Все флаги необязательны — запусти `multiai` без них, чтобы открыть интерактивный сеанс:

| Параметр | Кратко | Описание |
| --- | --- | --- |
| `--version` | `-V` | Вывести номер версии и завершить работу |
| `--help` | `-h` | Показать справку и завершить работу |
| `--session [id]` | `-S` | Продолжить сеанс. С идентификатором сразу открывает указанный сеанс, без него — интерактивный список выбора |
| `--continue` | `-c` | Продолжить последний сеанс в текущем рабочем каталоге без ручного указания идентификатора |
| `--model <model>` | `-m` | Выбрать псевдоним модели для этого запуска. Если параметр не указан, новые сеансы используют `default_model` из файла конфигурации |
| `--prompt <prompt>` | `-p` | Выполнить один запрос неинтерактивно и потоково вывести ответ ассистента в stdout. TUI в этом режиме не открывается |
| `--output-format <format>` | | Задать формат неинтерактивного вывода: `text` или `stream-json`. Используется только с `--prompt`; по умолчанию — `text` |
| `--yolo` | `-y` | Автоматически подтверждать обычные вызовы инструментов, пропуская запросы подтверждения |
| `--auto` | | Запустить автоматический режим разрешений: подтверждения инструментов обрабатываются автоматически, а агент не задаёт пользователю вопросы |
| `--plan` | | Запустить новый сеанс в Plan mode — ИИ отдаёт приоритет инструментам только для чтения, исследованию и планированию |
| `--skills-dir <dir>` | | Загружать Skills из указанного каталога вместо автоматически найденных пользовательских и проектных каталогов. Можно повторять |
| `--agent <name>` | | Запустить сеанс с указанным основным агентом (экспериментально, только для `multiai -p`) |
| `--agent-file <path>` | | Загрузить пользовательского агента из Markdown-файла и выбрать его для этого запуска (экспериментально, только для `multiai -p`). Нельзя повторять или сочетать с `--agent` |
| `--add-dir <dir>` | | Добавить в сеанс дополнительный рабочий каталог. Относительные пути вычисляются от текущего рабочего каталога. Можно повторять |

`-r` / `--resume` — скрытый псевдоним `--session`; `--yes` и `--auto-approve` — скрытые псевдонимы `--yolo`, которые не отображаются в справке.

::: warning Внимание
`--yolo` пропускает подтверждение обычных вызовов инструментов, включая запись файлов и выполнение команд оболочки. Используй его только в доверенных рабочих каталогах. Он не отменяет подтверждение выхода из Plan mode; на `Bash` внутри Plan mode действуют обычные правила разрешений.
:::

### Конфликты флагов

При запуске отклоняются следующие сочетания:

- `--continue` и `--session` взаимоисключающие: оба продолжают предыдущий сеанс;
- `--yolo` и `--auto` взаимоисключающие: эти режимы разрешений нельзя объединять;
- `--prompt` нельзя использовать с `--yolo`, `--auto` или `--plan`: неинтерактивный режим по умолчанию использует разрешения `auto`;
- `--output-format` используется только вместе с `--prompt`.

При продолжении сеанса сохранённый режим разрешений или Plan mode можно переопределить флагом `--auto`, `--yolo` или `--plan`. Например, `multiai --continue --auto` продолжит последний сеанс и включит автоматический режим разрешений.

## Основные сценарии

Начать новый сеанс:

```sh
multiai
```

Продолжить с места остановки, автоматически выбрав последний сеанс текущего каталога:

```sh
multiai --continue
```

Выбрать сеанс из истории или сразу указать известный идентификатор:

```sh
multiai --session
multiai --session 01HZ...XYZ
```

Пропустить запросы подтверждения для пакетных задач, безопасность которых известна заранее:

```sh
multiai --yolo
```

Позволить агенту действовать автономно и не задавать вопросы:

```sh
multiai --auto
```

Изучить код и подготовить план реализации до изменения файлов:

```sh
multiai --plan
```

### Пользовательские каталоги Skills

Каталоги Skills можно указать двумя способами с разным поведением:

- **`--skills-dir <dir>`** (флаг CLI) **заменяет** автоматически найденные пользовательские и проектные каталоги только для текущего запуска. Флаг можно повторять:

  ```sh
  multiai --skills-dir /path/to/team-skills --skills-dir ./local-skills
  ```

- **`extra_skill_dirs`** (`config.toml`) **добавляет** каталоги к автоматически найденным на постоянной основе. Это удобно для общих командных Skills. См. [Agent Skills](../customization/skills.md).

### Пользовательские агенты

`--agent` и `--agent-file` выбирают агента, управляющего сеансом. Сейчас оба параметра доступны только для `multiai -p` при `MULTIAI_EXPERIMENTAL_FLAG=1`; при другом запуске выводится понятная ошибка:

```sh
MULTIAI_EXPERIMENTAL_FLAG=1 multiai -p --agent reviewer "Review the changes on this branch"
```

`--agent-file` регистрирует один файл агента с наивысшим приоритетом только для текущего запуска и выбирает его. Флаг нельзя повторять, а `--agent` и `--agent-file` взаимоисключающие. Выбор закрепляется при первой привязке сеанса: продолжение с тем же `--agent` ничего не меняет, а попытка выбрать другого завершается ошибкой `already bound`. Формат файла и каталоги обнаружения описаны в разделе [Агенты и субагенты](../customization/agents.md#custom-agents).

## Неинтерактивное выполнение

Для одного запроса в скрипте или CI используй `-p`:

```sh
multiai -p "Summarize the current repository status"
```

Вывод оформлен как расшифровка: рассуждения и текст ассистента начинаются с `• `, а переносы строк получают отступ в два пробела. Текст ассистента отправляется в stdout; рассуждения, ход инструментов и уведомления о продолжении сеанса — в stderr. В режиме `-p` подтверждение пользователя не запрашивается: обычные инструменты работают по политике `auto`, но статические запреты продолжают действовать.

Временно сменить модель:

```sh
multiai -m multiai/kimi-for-coding -p "Explain the latest diff"
```

Для программного разбора используй `stream-json`: каждая строка stdout будет отдельным JSON-объектом:

```sh
multiai -p "List changed files" --output-format stream-json
```

В режиме `stream-json` обычные ответы создают сообщение ассистента. При вызове инструмента сначала выводится сообщение ассистента с `tool_calls`, затем соответствующее сообщение инструмента и последующие сообщения ассистента. Рассуждения в JSONL не записываются; ход инструментов и уведомления о продолжении сеанса остаются в stderr.

## Подкоманды

`multiai` предоставляет подкоманды `login`, `logout`, `account` (псевдоним `profile`), `acp`, `web`, `doctor`, `export`, `upgrade`, `vis` и `provider`. Устаревшая миграция и прежнее дерево команд `server` не включены.

### `multiai login`

Войти в учётную запись MultiAI без TUI. По умолчанию используется браузерный Authorization Code + PKCE; `--device` выбирает Device Authorization + PKCE. Refresh-токены хранятся в системном хранилище ключей, если `--session-only` явно не ограничивает их текущим процессом.

```sh
multiai login
multiai login --device
multiai login --session-only
```

| Параметр | Описание |
| --- | --- |
| `--device` | Показать код устройства вместо открытия браузера с локальным callback-адресом |
| `--session-only` | Хранить сеанс только до завершения процесса; обязательно для неинтерактивного запуска, если системное хранилище ключей недоступно |

Настройки OAuth-приложения, поведение токенов и особые случаи описаны в разделе [OAuth и учётная запись](../guides/account-and-oauth.md).

### `multiai logout`

По возможности отозвать refresh-токен, а затем в любом случае удалить локальный сеанс и управляемые модели MultiAI:

```sh
multiai logout
```

### `multiai account`

Показать профиль, баланс и состав кошелька, подписку, квоты, выданные области доступа, параметры подключения и замаскированные ключи API. `multiai profile` — псевдоним; `--json` выводит исходный снимок учётной записи:

```sh
multiai account
multiai profile
multiai account --json
```

### `multiai acp`

Переключить MultiAI CLI в режим ACP (Agent Client Protocol), в котором IDE управляет сеансами и вызовами инструментов через JSON-RPC по stdin/stdout. Обычно запускать эту команду вручную не нужно: IDE запускает её как подпроцесс. Настройка описана в разделе [Использование в IDE](../guides/ides.md), технические подробности — в [справочнике `multiai acp`](./multiai-acp.md).

```sh
multiai acp
```

### `multiai web`

Запустить локальный сервер MultiAI на переднем плане текущего терминала. Один процесс предоставляет REST + WebSocket API и веб-интерфейс с одного источника, а после готовности открывает интерфейс в браузере. Команда остаётся привязанной к терминалу и корректно завершается по `SIGINT` / `SIGTERM` (например, `Ctrl-C`).

При запущенном сервере `GET /openapi.json` возвращает документ OpenAPI для REST, а `GET /asyncapi.json` — локальный документ AsyncAPI для WebSocket.

```sh
multiai web                 # запустить сервер на переднем плане и открыть браузер
multiai web --no-open       # не открывать браузер
multiai web --port 58628    # выбрать порт
```

Несколько экземпляров могут использовать один домашний каталог: каждый регистрируется в `~/.multiai/server/instances/`, а при занятом порте пробуется `port + 1` (58628, 58629, …).

| Параметр | Описание |
| --- | --- |
| `--port <port>` | Порт привязки; по умолчанию `58627`; при занятости используется следующий порт |
| `--host [host]` | Хост привязки; без значения — `127.0.0.1` (только этот компьютер), пустой `--host` — `0.0.0.0` (все интерфейсы) |
| `--allowed-host <host...>` | Дополнительные значения заголовка Host, разрешённые проверкой защиты от DNS rebinding; можно повторять или перечислять через запятую |
| `--log-level <level>` | Включить журналы сервера выбранного уровня; по умолчанию отключены |
| `--debug-endpoints` | Подключить маршруты `/api/v1/debug/*` (по умолчанию выключены) |
| `--dangerous-bypass-auth` | Отключить bearer-аутентификацию для всех REST- и WebSocket-маршрутов, чтобы веб-интерфейс подключался без токена; только для доверенных сетей или за прокси с аутентификацией |
| `--no-open` | Не открывать браузер после готовности сервера |

По умолчанию `multiai web` слушает только локальный loopback-интерфейс и выводит bearer-токен в стартовом баннере; веб-интерфейс автоматически использует фрагмент URL `#token=` для входа.

::: danger Опасно
`--dangerous-bypass-auth` полностью отключает аутентификацию. Любой, кто может подключиться к порту, получит полный доступ к сеансам, файловой системе и оболочке. Используй этот режим только в доверенной сети или за собственным reverse proxy с аутентификацией и после работы останови сервер через `Ctrl-C`.
:::

#### `multiai web rotate-token`

Создать новый постоянный bearer-токен в `~/.multiai/server.token`; старый сразу перестаёт работать. Токен общий для домашнего каталога, поэтому все запущенные экземпляры подхватят его при следующей проверке без перезапуска.

### `multiai doctor`

Проверить `config.toml` и `tui.toml`, не запуская TUI и не изменяя файлы. По умолчанию проверяются файлы в `MULTIAI_HOME` (или `~/.multiai`, если переменная не задана). Отсутствующие файлы по умолчанию помечаются как пропущенные, поскольку могут применяться встроенные значения.

```sh
multiai doctor
```

| Команда | Описание |
| --- | --- |
| `multiai doctor` | Проверить стандартные `config.toml` и `tui.toml` |
| `multiai doctor config [path]` | Проверить только `config.toml`, при наличии `path` — указанный файл |
| `multiai doctor tui [path]` | Проверить только `tui.toml`, при наличии `path` — указанный файл |

Явно указанный файл должен существовать. Код завершения — `0`, если все проверенные файлы корректны или пропущены, и `1`, если запрошенный файл отсутствует или некорректен.

```sh
# Проверить стандартные файлы конфигурации
multiai doctor

# Проверить только стандартную конфигурацию среды выполнения
multiai doctor config

# Проверить новый TUI-файл перед заменой рабочего
multiai doctor tui ./tui.toml
```

### `multiai export`

Упаковать сеанс в ZIP-файл для передачи, архива или отчёта об ошибке.

```sh
multiai export [sessionId] [options]
```

| Параметр | Кратко | Описание |
| --- | --- | --- |
| `sessionId` | | Идентификатор экспортируемого сеанса. Если не указан, автоматически выбирается последний сеанс текущего каталога и запрашивается подтверждение |
| `--output <path>` | `-o` | Путь выходного ZIP-файла. По умолчанию используется стандартное имя в текущем каталоге |
| `--yes` | `-y` | Не запрашивать подтверждение стандартного сеанса и сразу экспортировать |
| `--no-include-global-log` | | Не включать глобальный диагностический журнал, который по умолчанию добавляется |

Экспорт содержит все файлы каталога выбранного сеанса. Глобальный диагностический журнал (`~/.multiai/logs/multiai.log`) добавляется по умолчанию и может содержать события других сеансов или проектов; чтобы не передавать его, укажи `--no-include-global-log`.

```sh
# Экспортировать последний сеанс текущего каталога без подтверждения
multiai export -y

# Экспортировать указанный сеанс по заданному пути
multiai export 01HZ...XYZ -o ./bug-report.zip

# Исключить глобальный диагностический журнал
multiai export 01HZ...XYZ -o ./bug-report.zip --no-include-global-log
```

### `multiai upgrade`

Немедленно проверить новую версию и показать предложение обновления; после выбора команда завершается. `multiai update` — её псевдоним.

```sh
multiai upgrade
```

Для глобальных установок через npm, pnpm, yarn, bun и нативных установок macOS / Linux команда показывает варианты обновления; пункт `Install update now` запускает соответствующую установку на переднем плане. Если текущий способ установки нельзя обновить автоматически (например, нативную установку Windows), выводится команда для ручного обновления.

### `multiai vis`

Запустить в браузере визуализатор сеанса для наблюдения за его выполнением. Команда поднимает встроенный сервер для локальных сеансов, выводит URL, открывает браузер и работает до нажатия `Ctrl-C`.

```sh
multiai vis [sessionId] [options]
```

| Параметр | Описание |
| --- | --- |
| `sessionId` | Сразу открыть указанный сеанс. Без значения открывается главная страница со списком сеансов |
| `--port <number>` | Порт привязки. По умолчанию автоматически выбирается свободный |
| `--host <host>` | Хост привязки. По умолчанию `127.0.0.1` |
| `--no-open` | Не открывать браузер автоматически, только вывести URL |

```sh
# Запустить визуализатор и открыть главную страницу
multiai vis

# Сразу открыть указанный сеанс
multiai vis 01HZ...XYZ

# Использовать заданные хост и порт без браузера, например на удалённой машине
multiai vis --host 0.0.0.0 --port 8123 --no-open
```

### `multiai provider`

Управлять провайдерами из оболочки — неинтерактивный аналог `/provider` в TUI. Подходит для сценариев развёртывания, инициализации CI и быстрой настройки нового компьютера.

```sh
multiai provider <action> [options]
```

Доступно пять действий.

#### `multiai provider add <url>`

Массово импортировать всех провайдеров из пользовательского реестра (`api.json`). Команда загружает реестр, создаёт записи `[providers.<id>]` и `[models.<alias>]` для каждого элемента и записывает метаданные `source`, чтобы при следующем запуске TUI автоматически обновил провайдеры и модели по тому же URL.

| Параметр | Описание |
| --- | --- |
| `<url>` | URL реестра |
| `--api-key <key>` | Bearer-токен для доступа к реестру. Если не указан, используется переменная окружения `MULTIAI_REGISTRY_API_KEY`; обязателен |

```sh
multiai provider add https://registry.example.com/v1/models/api.json --api-key YOUR_KEY

# Или через переменную окружения — удобно для CI / .envrc
MULTIAI_REGISTRY_API_KEY=YOUR_KEY multiai provider add https://registry.example.com/v1/models/api.json
```

Если идентификатор провайдера уже существует, он удаляется и создаётся заново. Модель по умолчанию автоматически не назначается; её можно выбрать позже через `-m` или `/model` в TUI.

#### `multiai provider remove <providerId>`

Удалить указанного провайдера и все псевдонимы его моделей. Если на него ссылается `default_model`, это значение также очищается.

```sh
multiai provider remove kohub
```

#### `multiai provider list`

Вывести каждого настроенного провайдера отдельной строкой с типом, количеством моделей и источником. Флаг `--json` выводит исходные таблицы `providers` и `models` для программной обработки.

```sh
multiai provider list
multiai provider list --json | jq '.providers | keys'
```

#### `multiai provider catalog list [providerId]`

Просмотреть публичный каталог моделей [models.dev](https://models.dev/), не изменяя конфигурацию. Без аргумента выводит всех провайдеров с типом протокола и числом моделей; с `providerId` — модели выбранного провайдера, размеры их контекста и возможности.

| Параметр | Описание |
| --- | --- |
| `[providerId]` | Необязательный идентификатор провайдера |
| `--filter <substring>` | Регистронезависимый фильтр по подстроке идентификатора или имени |
| `--url <url>` | Переопределить URL каталога; по умолчанию `https://models.dev/api.json` |
| `--json` | Вывести совпавшие записи в JSON |

```sh
multiai provider catalog list
multiai provider catalog list --filter anthropic
multiai provider catalog list anthropic
```

#### `multiai provider catalog add <providerId>`

Импортировать известного провайдера из каталога по идентификатору. Тип протокола, базовый URL и сведения о моделях берутся из каталога — нужен только ключ API. Провайдеры, для которых каталог не указывает протокол (например, xai, openrouter и другие со специальными SDK), импортируются как OpenAI-совместимые, а вывод сообщает об этом предположении. Если в каталоге нет подходящей конечной точки, обязателен `--base-url`. Проприетарные протоколы, например Amazon Bedrock, импортировать нельзя.

| Параметр | Описание |
| --- | --- |
| `<providerId>` | Идентификатор провайдера в каталоге, например `anthropic` или `openai` |
| `--api-key <key>` | Ключ API провайдера. Если не указан, используется `MULTIAI_REGISTRY_API_KEY`; обязателен |
| `--default-model <modelId>` | Необязательно: после импорта задать `default_model` как `<providerId>/<modelId>` |
| `--base-url <url>` | Переопределить конечную точку каталога; обязателен, если она отсутствует или содержит только переменную окружения |
| `--url <url>` | Переопределить URL каталога; по умолчанию `https://models.dev/api.json` |

```sh
multiai provider catalog list anthropic          # Сначала просмотреть модели
multiai provider catalog add anthropic --api-key sk-ant-... --default-model claude-opus-4-7
```
