# Хуки

Хуки — это механизм автоматических триггеров: вы заранее указываете MultiAI CLI: «каждый раз, когда происходит X, запускай этот скрипт». Скрипт выполняется на вашем локальном компьютере и может содержать любую логику. Типичные сценарии:

- **Перехват в целях безопасности**: перед выполнением агентом команды оболочки проверить, нет ли в ней опасных операций (например, `rm -rf`), и при необходимости заблокировать выполнение.
- **Уведомления рабочего стола**: после завершения фоновой задачи показать системное уведомление, чтобы вы вернулись и проверили результат.
- **Автоматические проверки**: при каждой отправке сообщения пользователем автоматически добавлять в контекст справочные сведения, например текущую ветку Git.

## Как работают хуки

Для правила хука необходимо указать три вещи: **какое событие служит триггером**, **какие цели должны совпасть** и **какой скрипт запустить**.

При срабатывании CLI упаковывает сведения о событии — причину запуска, имя инструмента, содержимое команды и т. д. — в JSON и передаёт их скрипту через **стандартный ввод** (stdin). Скрипт читает эти данные и решает, какой ответ вернуть.

Ответ скрипта определяется двумя составляющими:

- **Код завершения**: `0` означает разрешить, `2` — заблокировать, другие ненулевые значения по умолчанию означают разрешить.
- **Стандартный вывод** (stdout): может содержать поясняющий текст.

Даже если скрипт завершится с ошибкой или превысит тайм-аут, CLI **не прервёт вашу работу**. Такой подход называется fail-open («разрешить при сбое») и не позволяет ошибкам хуков становиться препятствием для работы.

::: warning Примечание
Именно из-за поведения fail-open хуки подходят для оповещений и лёгкого перехвата, но **не должны быть единственной защитой**. Для действительно рискованных операций полагайтесь на подтверждение разрешений и ручную проверку.
:::

## Быстрый старт: минимальный хук

Следующий хук показывает уведомление в строке заголовка терминала при каждом завершении фоновой задачи (в macOS необходимо установить `terminal-notifier`):

```toml
# Запишите в ~/.multiai/config.toml
[[hooks]]
event = "Notification"           # Триггер: изменение состояния фоновой задачи
matcher = "task\\.completed"     # Нас интересуют только уведомления "completed"
command = "terminal-notifier -title MultiAI -message 'Task done'"
```

Сохраните конфигурацию и начните новый сеанс. При следующем завершении фоновой задачи появится уведомление.

## Настройка

Все правила хуков записываются в массив `[[hooks]]` файла `~/.multiai/config.toml`; каждая запись задаёт одно правило:

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `event` | `string` | Да | Имя события-триггера; должно присутствовать в таблице «Справочник событий» ниже |
| `matcher` | `string` | Нет | Регулярное выражение для фильтрации целей события; если не указано, совпадает со всеми |
| `command` | `string` | Да | Команда оболочки, запускаемая при срабатывании |
| `timeout` | `integer` | Нет | Тайм-аут в секундах от 1 до 600; по умолчанию 30 секунд |

В `[[hooks]]` разрешены только эти четыре поля; дополнительные поля приведут к ошибке загрузки файла конфигурации.

**Если одному событию соответствуют несколько правил**, все подходящие хуки запускаются параллельно; несколько правил с одинаковым значением `command` выполняются только один раз.

Рабочим каталогом команд хуков служит каталог проекта текущего сеанса. На платформах, отличных от Windows, процессы хуков помещаются в отдельную группу процессов; при превышении тайм-аута сначала отправляется сигнал, дающий процессу возможность корректно завершиться, а затем процесс принудительно останавливается.

### Формат данных события

При каждом срабатывании хука CLI передаёт скрипту через stdin следующие базовые сведения:

```json
{
  "hook_event_name": "PreToolUse",
  "session_id": "session_abc",
  "cwd": "/path/to/project"
}
```

Для конкретных событий добавляются дополнительные поля, например имя инструмента и содержимое команды; см. справочник событий ниже. Все имена полей записываются в snake_case.

## Возвращаемые значения

После завершения скрипта CLI определяет намерение хука по коду завершения:

| Код завершения | Значение | Поведение CLI |
| --- | --- | --- |
| `0` | Обычное завершение, разрешить | Продолжить выполнение; содержимое stdout (если есть) может быть добавлено в контекст |
| `2` | Намеренная блокировка | Остановить текущую операцию; содержимое stderr (выведенное через `console.error`) используется как причина блокировки |
| Другой ненулевой | Ошибка скрипта | По умолчанию разрешить (fail-open) |
| Тайм-аут или сбой | Исключение скрипта | По умолчанию разрешить (fail-open) |

Для блокировки также можно вернуть через stdout объект JSON:

```json
{
  "hookSpecificOutput": {
    "permissionDecision": "deny",
    "permissionDecisionReason": "Please use rg instead of grep"
  }
}
```

::: info Какие события поддерживают блокировку?
Возвращаемые значения влияют на основной поток только у **блокируемых событий** (`PreToolUse`, `Stop`, `UserPromptSubmit`). Все остальные события предназначены **только для наблюдения**: они запускаются без ожидания результата, и ответ скрипта никак не влияет на основной поток.
:::

## Справочник событий

| Событие | С чем сопоставляется matcher | Поддерживает блокировку? | Описание |
| --- | --- | --- | --- |
| `UserPromptSubmit` | Текст, отправленный пользователем | ✓ | Срабатывает при отправке сообщения пользователем; возвращённый текст добавляется в контекст; при блокировке модель не вызывается на этом ходу |
| `PreToolUse` | Имя инструмента | ✓ | Срабатывает перед вызовом инструмента (до проверки разрешений); при блокировке инструмент не выполняется |
| `Stop` | Пустая строка | ✓ | Срабатывает, когда модель собирается завершить текущий ход; при блокировке можно добавить сообщение, чтобы модель продолжила работу |
| `PostToolUse` | Имя инструмента | — | Срабатывает после успешного выполнения инструмента (только наблюдение) |
| `PostToolUseFailure` | Имя инструмента | — | Срабатывает после ошибки или блокировки инструмента (только наблюдение) |
| `PermissionRequest` | Имя инструмента | — | Срабатывает непосредственно перед ожиданием подтверждения пользователя (только наблюдение) |
| `PermissionResult` | Имя инструмента | — | Срабатывает после завершения подтверждения (только наблюдение) |
| `SessionStart` | `startup` или `resume` | — | Срабатывает после начала нового или возобновления предыдущего сеанса |
| `SessionEnd` | `exit` | — | Срабатывает после закрытия сеанса |
| `SubagentStart` | Имя субагента | — | Срабатывает перед началом работы субагента |
| `SubagentStop` | Имя субагента | — | Срабатывает после успешного завершения субагента (только наблюдение) |
| `StopFailure` | Тип ошибки | — | Срабатывает после сбоя текущего хода из-за ошибки (только наблюдение) |
| `Interrupt` | Пустая строка | — | Срабатывает, когда пользователь прерывает текущий ход (например, нажатием Esc); не срабатывает при тайм-аутах и других программных прерываниях. При прерывании `Stop` не срабатывает, поэтому вместо него запускается это событие. Полезная нагрузка содержит поле `reason` (только наблюдение) |
| `PreCompact` | `manual` или `auto` | — | Срабатывает перед началом сжатия контекста; возвращаемые значения полностью игнорируются |
| `PostCompact` | `manual` или `auto` | — | Срабатывает после завершения сжатия контекста (только наблюдение) |
| `Notification` | Тип уведомления (например, `task.completed`) | — | Срабатывает при изменении состояния фоновой задачи (только наблюдение) |

## Пример: блокировка опасных команд оболочки

Следующий хук проверяет содержимое команды перед вызовом агентом инструмента `Bash` и блокирует её при обнаружении `rm -rf`:

```toml
[[hooks]]
event = "PreToolUse"
matcher = "Bash"
command = "node ~/.multiai/hooks/block-dangerous-bash.mjs"
timeout = 5
```

```js
// block-dangerous-bash.mjs
// Читаем из stdin данные события, переданные CLI
let input = '';
process.stdin.on('data', (chunk) => { input += chunk; });
process.stdin.on('end', () => {
  const payload = JSON.parse(input);         // Разбираем данные события
  const command = payload.tool_input?.command ?? '';

  if (command.includes('rm -rf')) {
    // Объясняем причину через stderr; код завершения 2 означает блокировку
    console.error('Dangerous command detected, blocked');
    process.exit(2);
  }
  // Обычное завершение (код 0) означает разрешение
});
```

После блокировки MultiAI CLI записывает причину в контекст, и модель может выбрать более безопасный вариант.

::: warning Примечание
Этот пример лишь демонстрирует механизм блокировки и не является полноценным анализатором безопасности для рабочей среды. В реальных сценариях лучше применять списки разрешённых команд или специализированный анализатор оболочки, учитывающий кавычки, подстановку переменных и последовательности из нескольких команд.
:::
