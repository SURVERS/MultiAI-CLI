# Model Context Protocol

[Model Context Protocol (MCP)](https://modelcontextprotocol.io/) — открытый протокол, который позволяет моделям безопасно вызывать инструменты, предоставленные внешними процессами или сервисами: например, читать задачи GitHub, выполнять запросы к базам данных или работать с локальной файловой системой. MultiAI CLI выступает клиентом MCP, подключает эти внешние инструменты и предоставляет их агенту наряду со встроенными инструментами (`Read`, `Bash`, `Grep` и другими) без различий в поведении.

## Способы подключения

MultiAI CLI поддерживает три способа подключения к серверам MCP:

- **stdio**: CLI запускает локальный сервер MCP как дочерний процесс и обменивается с ним данными через стандартные потоки ввода и вывода. Подходит для локальных инструментов командной строки.
- **HTTP**: CLI подключается к уже запущенной конечной точке HTTP. Подходит для удалённых сервисов и процессов, которые должны работать постоянно.
- **SSE**: CLI подключается к устаревшей конечной точке HTTP+SSE (Server-Sent Events — механизм потоковой передачи данных по HTTP). Для новых серверов MCP выбирайте HTTP, а `transport: "sse"` используйте, только если сервис по-прежнему предоставляет лишь старый транспорт SSE.

## Настройка

Серверы MCP настраиваются в файле `mcp.json` на двух уровнях:

- **Уровень пользователя**: `~/.multiai/mcp.json` (или `$MULTIAI_HOME/mcp.json`), общий для всех проектов.
- **Уровень проекта**: `.multiai/mcp.json` в рабочем каталоге, действует только для текущего репозитория.

Если записи имеют одинаковое имя, запись уровня проекта получает приоритет и переопределяет пользовательскую.

Выполните `/mcp-config` в TUI, чтобы интерактивно добавлять, изменять и удалять серверы без ручного редактирования JSON. Команда `/mcp` показывает состояние подключения всех текущих серверов.

Структура `mcp.json`:

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"]
    },
    "linear": {
      "url": "https://mcp.linear.app/mcp"
    },
    "legacy-events": {
      "transport": "sse",
      "url": "https://mcp.example.com/sse"
    }
  }
}
```

Записи с полем `command` задают серверы stdio, а записи с полем `url` без `transport` — серверы HTTP. Для устаревших серверов SSE явно укажите для `transport` значение `"sse"`.

Необязательные поля:

| Поле | Тип | Применяется к | Описание |
| --- | --- | --- | --- |
| `env` | `Record<string, string>` | stdio | Переменные окружения, передаваемые дочернему процессу |
| `cwd` | `string` | stdio | Рабочий каталог дочернего процесса |
| `headers` | `Record<string, string>` | HTTP, SSE | Статические заголовки, добавляемые к каждому запросу |
| `bearerTokenEnvVar` | `string` | HTTP, SSE | Имя переменной окружения, содержащей Bearer-токен |
| `enabled` | `boolean` | Все | Установите `false`, чтобы отключить сервер |
| `startupTimeoutMs` | `number` | Все | Тайм-аут подключения от `1` до `2147483647` миллисекунд; по умолчанию `30000` |
| `toolTimeoutMs` | `number` | Все | Тайм-аут отдельного вызова инструмента от `1` до `2147483647` миллисекунд |
| `enabledTools` | `string[]` | Все | Список разрешённых инструментов |
| `disabledTools` | `string[]` | Все | Список запрещённых инструментов |

Тайм-аут подключения и отдельного вызова инструмента необязательно задавать для каждого сервера: `[mcp] startup_timeout_ms` и `[mcp] tool_timeout_ms` в `config.toml` либо переменные окружения `MULTIAI_MCP_STARTUP_TIMEOUT_MS` и `MULTIAI_MCP_TOOL_TIMEOUT_MS` изменяют глобальные значения по умолчанию. Приоритет таков: поле сервера > переменная окружения > `config.toml` > встроенное значение по умолчанию. Подробнее см. в разделе [«Файлы конфигурации»](../configuration/config-files.md#mcp).

Серверы HTTP и SSE позволяют передавать статические учётные данные через `headers` или `bearerTokenEnvVar`. Если требуется OAuth, выполните `/mcp-config login <server-name>`, чтобы пройти авторизацию в браузере.

Плагины также могут объявлять серверы MCP в своём манифесте. Объявленные плагином серверы включены по умолчанию; их можно отключить или снова включить через `/plugins`, после чего необходимо начать новый сеанс. Подробнее см. в разделе [«Плагины»](./plugins.md).

::: warning Примечание
Записи stdio из проектного файла `.multiai/mcp.json` выполняют локальные команды при запуске сеанса. Включайте их только в репозиториях, которым доверяете.
:::

## Имена инструментов и разрешения

Инструменты MCP получают имена в формате `mcp__<server>__<tool>`, например `mcp__github__create_issue`. Правила разрешений поддерживают подстановочные знаки `*` и `**`: например, `mcp__github__*` соответствует всем инструментам этого сервера. Параметры инструментов MCP при сопоставлении разрешений не учитываются.

Вызовы, не соответствующие ни одному правилу разрешений, вызывают запрос подтверждения. Если в диалоге подтверждения выбрать «Разрешить для этого сеанса», последующие вызовы того же типа будут автоматически разрешены в текущем сеансе.

Постоянные правила также можно заранее задать в `[[permission.rules]]` файла `config.toml`:

```toml
[[permission.rules]]
decision = "allow"
pattern = "mcp__github__*"

[[permission.rules]]
decision = "deny"
pattern = "mcp__filesystem__write_file"
```

Полный синтаксис правил разрешений приведён в разделе [«Файлы конфигурации»](../configuration/config-files.md#permission).

## Безопасность

При подключении к внешним серверам MCP соблюдайте следующие меры:

- Подключайтесь только к серверам из доверенных источников.
- Проверяйте, что имена и параметры инструментов в запросах подтверждения выглядят разумно.
- Сохраняйте ручное подтверждение для инструментов с высоким риском (запись файлов, выполнение команд и т. п.); не используйте подстановочные шаблоны `mcp__*`, разрешающие сразу все инструменты.

::: warning Примечание
В YOLO mode вызовы инструментов MCP подтверждаются автоматически. Используйте этот режим, только если полностью доверяете подключённым серверам MCP.
:::
