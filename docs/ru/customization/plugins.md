# Плагины

Плагины упаковывают многократно используемые возможности MultiAI CLI в устанавливаемые модули: они
могут добавлять [Agent Skills](./skills.md), загружать Skill при запуске сеанса и объявлять
серверы MCP. Поддерживаются локальные плагины и пользовательские источники GitHub/URL.

## Установка и управление

Выполните `/plugins` в TUI, чтобы открыть диспетчер плагинов. MultiAI CLI поставляется без
встроенного магазина. Вкладка **Installed** управляет локальными установками, **Custom** принимает
URL, а вкладки магазинов заполняются только после явной настройки пользовательского
каталога.

| Клавиша | Действие |
| --- | --- |
| `Tab` / `Shift-Tab` | Переключение между вкладками Installed / Official / Third-party / Custom |
| `Space` | Включить или отключить выбранный установленный плагин (вкладка Installed) |
| `D` | Удалить выбранный установленный плагин (вкладка Installed) |
| `M` | Управлять серверами MCP выбранного плагина (вкладка Installed) |
| `R` | Перезагрузить `installed.json` и все манифесты (вкладка Installed) |
| `Enter` | Вкладка Installed: установить доступное обновление или, если версия актуальна, показать сведения · Вкладка Official/Third-party: установить или обновить · Вкладка Custom: установить |
| `I` | Показать сведения о плагине (вкладка Installed) |
| `Esc` | Вернуться назад или отменить действие |

Также можно напрямую использовать команды с косой чертой:

| Команда | Описание |
| --- | --- |
| `/plugins` | Открыть интерактивный диспетчер плагинов |
| `/plugins list` | Показать установленные плагины |
| `/plugins install <path-or-url>` | Установить из локального каталога, URL zip-архива или URL репозитория GitHub |
| `/plugins marketplace <source>` | Открыть явно указанный путь или URL JSON магазина |
| `/plugins info <id>` | Показать сведения и диагностику плагина |
| `/plugins enable <id>` | Включить плагин |
| `/plugins disable <id>` | Отключить плагин |
| `/plugins remove <id>` | Удалить плагин (требуется подтверждение) |
| `/plugins reload` | Перезагрузить `installed.json` и все манифесты плагинов |
| `/plugins mcp enable <id> <server>` | Включить объявленный плагином сервер MCP |
| `/plugins mcp disable <id> <server>` | Отключить объявленный плагином сервер MCP |

На вкладке **Installed** перечислены установленные плагины. Вкладка **Custom** устанавливает их по
URL. Если каталог не настроен, просмотр магазина сообщает, что он
отключён. Любая пользовательская установка считается сторонней и требует явного
подтверждения.

### Установка из GitHub

Используйте `/plugins install <url>`, чтобы установить плагин непосредственно из репозитория GitHub. Поддерживаются четыре формы URL:

- `https://github.com/<owner>/<repo>`: установить последний релиз; если релизов нет, используется ветка по умолчанию.
- `https://github.com/<owner>/<repo>/tree/<ref>`: установить конкретную ветку, тег или короткий SHA коммита.
- `https://github.com/<owner>/<repo>/releases/tag/<tag>`: закрепить конкретный тег.
- `https://github.com/<owner>/<repo>/commit/<sha>`: закрепить конкретный коммит.

Сетевые запросы проходят только через перенаправления `github.com` и загрузки `codeload.github.com`; `api.github.com` не вызывается.

### Примечания

- Изменения плагинов применяются после `/reload` или в новых сеансах. После установки, включения, отключения или удаления плагина выполните `/reload` или `/new`; текущий сеанс не обновится.
- Локальные установки копируются в `$MULTIAI_HOME/plugins/managed/<id>/`, и CLI всегда запускает плагин из этой управляемой копии. Изменение исходного каталога после установки не даст эффекта — плагин нужно переустановить.
- При удалении плагина удаляется только запись об установке; управляемая копия и исходные файлы остаются на диске.
- Сейчас плагины устанавливаются для пользователя и действуют во всех проектах; установка на уровне проекта пока не поддерживается.

### Пользовательский JSON магазина

Передайте путь или URL пользовательского JSON магазина команде `/plugins marketplace <source>`
либо задайте [`MULTIAI_PLUGIN_MARKETPLACE_URL`](../configuration/env-vars.md). Каталога
по умолчанию нет. Каждой записи нужны `id` и `source`:

```json
{
  "version": "2",
  "plugins": [
    {
      "id": "my-plugin",
      "displayName": "My Plugin",
      "source": "./my-plugin"
    }
  ]
}
```

## Манифест плагина

Плагин — это каталог или zip-файл с манифестом. Манифест может находиться в одном из следующих мест:

```text
<plugin_root>/kimi.plugin.json
<plugin_root>/.kimi-plugin/plugin.json
```

Эти устаревшие имена файлов манифеста по-прежнему поддерживаются, чтобы существующие локальные плагины
продолжали работать; они обозначают формат файла, а не управляемый сервис MultiAI.

Если существуют оба файла, приоритет имеет `kimi.plugin.json`.

Пример:

```json
{
  "name": "kimi-finance",
  "version": "1.0.0",
  "description": "Finance data and analysis workflows for MultiAI CLI",
  "skills": "./skills/",
  "sessionStart": {
    "skill": "using-finance"
  },
  "interface": {
    "displayName": "Example Finance",
    "shortDescription": "Market data and financial analysis workflows"
  }
}
```

Поддерживаемые поля:

| Поле | Описание |
| --- | --- |
| `name` | Обязательное; служит идентификатором плагина. Должно соответствовать `[a-z0-9][a-z0-9_-]{0,63}` |
| `version`, `description`, `keywords`, `author`, `homepage`, `license` | Отображаемые метаданные |
| `interface` | Поля, показываемые в `/plugins`: `displayName`, `shortDescription`, `longDescription`, `developerName`, `websiteURL` |
| `skills` | Один или несколько путей `./`; должны находиться внутри корневого каталога плагина. Если поле отсутствует, корневой `SKILL.md` считается единственным корнем Skill |
| `sessionStart.skill` | Загружает указанный Skill плагина в основной агент при запуске нового или возобновлённого сеанса |
| `skillInstructions` | Дополнительные инструкции, добавляемые при каждой загрузке Skill из этого плагина |
| `mcpServers` | Объявления серверов MCP; включены по умолчанию, могут быть отключены через `/plugins` |
| `hooks` | Правила хуков, выполняемые при событиях жизненного цикла, пока плагин включён; см. [«Хуки в плагинах»](#хуки-в-плагинах) |
| `commands` | Один или несколько путей `./` к каталогу или файлу `.md`; регистрирует находящиеся там файлы Markdown как команды с косой чертой. См. [«Команды плагина с косой чертой»](#команды-плагина-с-косой-чертой) |

Неподдерживаемые поля среды выполнения, например `tools`, `apps`, `inject` и `configFile`, показываются в диагностике и игнорируются.

## Команды плагина с косой чертой

Команды с косой чертой сохраняют часто используемый запрос как `/command`, чтобы запускать его вводом команды, а не набирать целиком заново.

Ниже приведён минимальный полный пример. Структура каталога плагина:

```text
kimi-finance/
  kimi.plugin.json
  commands/
    report.md
```

В манифесте (`kimi.plugin.json`) поле `commands` указывает расположение файлов команд:

```json
{
  "name": "kimi-finance",
  "version": "1.0.0",
  "commands": "./commands/"
}
```

Файл команды `commands/report.md`. Блок между двумя верхними строками `---` — это frontmatter (метаданные команды), а всё ниже — запрос, отправляемый агенту:

```markdown
---
description: Pull and summarize a stock's latest financials
---

Pull the latest financials for $ARGUMENTS and summarize revenue, profit, and key risks.
```

После установки и включения плагина введите в чате:

```text
/kimi-finance:report TSLA
```

MultiAI заменит `$ARGUMENTS` в теле на `TSLA`, а затем выполнит запрос. Три следующих подраздела подробно описывают каждый шаг.

### Объявление команд (поле `commands`)

`commands` принимает один путь `./` или массив путей; каждый из них должен указывать на каталог либо файл `.md` внутри корня плагина:

- **Каталог**: рекурсивно собираются все файлы `.md`, каждый из которых становится отдельной командой.
- **Один файл `.md`**: регистрируется только этот файл.
- Файл не `.md` или отсутствующий путь: отображается в диагностике (в панели `/plugins`) и игнорируется.

### Создание файла команды

Файл команды состоит из двух частей: необязательного **frontmatter** (метаданные между двумя верхними строками `---`, где задаются `name` и `description`) и **тела** (запрос после `---`). Для пропущенных полей используются следующие значения:

- `name` (имя команды): выводится из пути к файлу относительно объявленного пути `commands` (без `.md`, с разделителями `/`), например `commands/frontend/component.md` → `frontend/component`. Значение `name` из frontmatter имеет приоритет.
- `description` (показывается в списке команд): первая непустая строка тела (обрезается после 240 символов); если тело также пустое, показывается `No description provided.`.

### Запуск команд и передача аргументов

К командам добавляется префикс идентификатора плагина — их пространство имён — и они регистрируются как `<plugin>:<command>`. Поэтому приведённая выше команда на самом деле называется `/kimi-finance:report`; это предотвращает конфликты одноимённых команд разных плагинов.

Всё, что введено после команды, заменяет `$ARGUMENTS` в теле (в примере выше `TSLA` заменяет `$ARGUMENTS`). Если в теле нет `$ARGUMENTS`, но аргументы переданы, они не теряются, а добавляются в конец тела как `ARGUMENTS: <введённый текст>`.

## Skills и запуск сеанса

Skills плагина используют тот же формат `SKILL.md`, что и обычные [Agent Skills](./skills.md). Типичная структура каталога:

```text
my-plugin/
  kimi.plugin.json
  skills/
    using-my-plugin/
      SKILL.md
    another-workflow/
      SKILL.md
```

`sessionStart.skill` загружает Skill плагина в основной агент при запуске сеанса. Это подходит для инструкций инициализации, правил рабочего процесса или сопоставления терминов других инструментов с MultiAI CLI. Поле лишь внедряет текст и не выполняет код.

Независимо от способа загрузки Skill (`sessionStart.skill`, `/skill:<name>` или автоматический вызов моделью), рядом со Skill этого плагина добавляется `skillInstructions`.

## Серверы MCP в плагинах

Если плагину нужны реальные возможности инструментов, он может объявить `mcpServers` в манифесте, повторно используя схему [MCP](./mcp.md).

Сервер stdio (локальная команда):

```json
{
  "mcpServers": {
    "finance": {
      "command": "uvx",
      "args": ["kimi-finance-mcp"]
    }
  }
}
```

Сервер HTTP (удалённый сервис):

```json
{
  "mcpServers": {
    "docs": {
      "url": "https://example.com/mcp"
    }
  }
}
```

Для серверов stdio значение `command` может быть командой из `PATH` или путём внутри корневого каталога плагина, начинающимся с `./`. Поле `cwd` также должно начинаться с `./` и указывать внутрь корня плагина, иначе сервер игнорируется.

Серверы MCP плагинов запускаются после `/reload` или в новых сеансах. Чтобы включить или отключить сервер:

```sh
/plugins mcp disable kimi-finance finance
/reload

/plugins mcp enable kimi-finance finance
/reload
```

## Хуки в плагинах

Плагин может объявить в манифесте правила хуков, выполняемые при событиях жизненного цикла, пока плагин включён. Каждая запись использует те же поля, что правило [`[[hooks]]` в `config.toml`](./hooks.md#настройка): `event`, `matcher`, `command`, `timeout`:

```json
{
  "hooks": [
    {
      "event": "PreToolUse",
      "matcher": "Bash",
      "command": "node ./hooks/check-bash.mjs",
      "timeout": 5
    }
  ]
}
```

Хуки плагинов используют тот же механизм, что и глобальные хуки. Список событий, полезную нагрузку JSON в stdin и влияние кодов завершения и возвращаемых значений на основной поток см. в разделе [«Хуки»](./hooks.md). Отличия:

- Хуки плагина активны, только пока плагин **включён**; при отключении плагина его хуки перестают работать.
- Рабочим каталогом каждого хука становится корень плагина, поэтому `command` может использовать внутренние пути `./`.
- Процесс хука получает две дополнительные переменные окружения: `MULTIAI_HOME` и `MULTIAI_PLUGIN_ROOT` (корневой каталог плагина).

Сама по себе установка плагина никогда не запускает его хуки: они срабатывают только при соответствующем событии, пока плагин включён.

## Модель безопасности

Область загрузки плагинов ограничена. При установке или запуске сеанса не происходят следующие операции:

- Инструменты плагинов командного типа и устаревшие среды выполнения инструментов не запускаются.
- После разрешения символических ссылок все пути должны оставаться внутри корневого каталога плагина.
- Серверы MCP включённых плагинов запускаются после `/reload` или в новых сеансах и могут быть в любой момент отключены через `/plugins`.
- Повреждённые манифесты и небезопасные пути отображаются в диагностике `/plugins info <id>` и не влияют на другие сеансы.
