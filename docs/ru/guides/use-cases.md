# Распространённые сценарии

На этой странице собраны типичные сценарии использования MultiAI CLI и готовые примеры запросов — копируйте их как есть или адаптируйте под свои задачи.

## Изучение незнакомого проекта

При знакомстве с незнакомым репозиторием полезно сначала выполнить `multiai --plan` или нажать `Shift-Tab`, чтобы перейти в Plan mode: тогда перед любыми изменениями агент выведет план исследования.

```
Дай обзор архитектуры этого репозитория. В частности:
1. Где находится точка входа и что происходит при запуске?
2. Как основные модули зависят друг от друга?
3. Как загружаются конфигурация и данные?
В конце нарисуй простую схему зависимостей модулей.
```

Можно сосредоточиться и на конкретном вопросе:

```
Как работает цикл событий в src/runtime? Где возникают события и что их обрабатывает?
```

```
Как в этом проекте реализовано «подтверждение разрешений»? Какие файлы задействованы и какие типы являются ключевыми?
```

Для масштабных исследований основной агент может поручить **субагентам** параллельное выполнение подзадач. Подробнее см. в разделе [Агенты и субагенты](../customization/agents.md).

## Реализация новой возможности

Чётко опишите требования и критерии приёмки. Для сложных изменений используйте Plan mode, чтобы подтвердить подход до начала работы:

```
Добавь вспомогательную функцию повторных попыток в src/utils:
- Сигнатура: retry<T>(fn: () => Promise<T>, options): Promise<T>
- Параметры: maxAttempts, initialDelayMs, backoffFactor
- При неудаче выбрасывай ошибку последней попытки
- Добавь набор модульных тестов: успех с первой попытки, успех после повторов и неудача всех попыток
```

Если результат не подходит, просто опишите нужное изменение — вручную редактировать ничего не требуется:

```
Для расчёта задержки использовано фиксированное значение. Добавь случайный разброс, чтобы избежать эффекта лавины запросов. Обнови реализацию и тесты.
```

## Исправление ошибки

Сразу укажите проявление ошибки, шаги воспроизведения и ожидаемое поведение, чтобы избежать дополнительных уточнений:

```
При запуске npm test иногда возникает ошибка:

  TypeError: Cannot read properties of undefined (reading 'id')
      at SessionStore.update (src/session/store.ts:142:18)

Она появляется только в тестах, где одновременно запускается несколько обновлений. Найди причину, исправь её и запусти полный набор тестов для проверки.
```

Если первопричина неясна, сначала попросите агента провести исследование без изменений:

```
Отзыв пользователя: после успешного входа первое обновление страницы возвращает на страницу входа, а второе работает нормально. Сначала найди наиболее вероятные причины и перечисли самые подозрительные места. Я подтвержу направление до начала изменений.
```

Для чисто механических задач агенту можно дать свободу действий:

```
Запусти набор тестов, исправь все неработающие тесты, затем запусти его снова и убедись, что всё проходит.
```

## Написание тестов и рефакторинг

Задачи с чёткими границами и явными критериями приёмки особенно хорошо подходят агенту:

```
Для src/parser/markdown.ts почти нет тестов. Добавь набор модульных тестов для обычных абзацев, вложенных списков, блоков кода, таблиц, цитат и смешанного содержимого. Следуй уже принятому в проекте стилю тестов.
```

```
Вынеси повторяющийся шаблон «прочитать тело → проверить → записать в журнал → ответить» из src/handlers в промежуточный обработчик. После этого запусти тесты и убедись, что существующее поведение не изменилось.
```

Перед рефакторингом нескольких файлов используйте Plan mode для подтверждения подхода. Можно также создать экспериментальное ответвление командой `/fork`: если результат не понравится, просто вернитесь к исходному сеансу.

## Разовые скрипты и автоматизация

Пакетные изменения файлов, сбор статистики и сравнительные исследования можно выполнить одним запросом:

```
Замени все объявления var в файлах .js внутри src на const или let, по возможности выбирая const. После завершения запусти lint для проверки.
```

```
Проанализируй журналы доступа в logs/ за последние 7 дней. Для каждого пути API вычисли количество вызовов и время ответа p50 и p99, затем выведи результаты в виде таблицы Markdown.
```

```
Исследуй основные варианты внедрения зависимостей для TypeScript (tsyringe, inversify, awilix). Сравни их по трём параметрам: стиль API, требования к декораторам и накладные расходы во время выполнения. Дай рекомендацию объёмом не больше страницы.
```

Для безопасных пакетных задач используйте `--yolo` или `/yolo`, чтобы пропустить запросы подтверждения, либо добавьте предварительно разрешённые правила для конкретных инструментов в [файлы конфигурации](../configuration/config-files.md#permission).

## Запланированные задачи и напоминания

В интерактивном сеансе можно попросить агента создать разовое напоминание или повторяющуюся задачу. Агент сформирует cron-выражение в вашем местном часовом поясе и в нужное время снова добавит запрос в тот же сеанс:

```
Напомни мне в 14:30 проверить развёртывание.
```

```
Каждый будний день в 9:00 присылай сводку последних сбоев CI.
```

```
Каждый час проверяй конечную точку состояния рабочей среды и сообщай, если что-то не так.
```

```
Вернись примерно через 10 минут и проверь, завершилась ли сборка.
```

Запланированные задачи привязаны к сеансу: терминал можно закрыть, а после возобновления того же сеанса через `multiai --session` они загрузятся и продолжат выполняться. В новые сеансы они не переносятся. Повторяющиеся задачи истекают через 7 дней: при последнем запуске агент получает сигнал `stale` и по исходным инструкциям решает, остановить или продлить задачу.

Чтобы узнать об ожидающих задачах, просто спросите агента — он вызовет инструмент только для чтения `CronList`. Для отмены попросите удалить задачу или укажите её восьмизначный идентификатор. Полное описание приведено в разделе [Запланированные задачи](../reference/tools.md#scheduled-tasks). Глобальное отключение задаётся через `MULTIAI_DISABLE_CRON=1`.

## Создание и сопровождение документации

```
Я изменил сигнатуру интерфейса в src/auth/login.ts. Обнови соответствующий JSDoc, пример кода в README и все абзацы в docs/en/guides, где упоминается этот интерфейс.
```

```
Добавь к каждой публичной функции в src/api без docstring документационный комментарий в стиле уже существующих.
```

```
На основе реализации команд в src/cli подготовь черновик справочника с каждой подкомандой, её аргументами и значениями по умолчанию. Помести его в docs/en/reference для последующей проверки.
```

Если нужна запись или ретроспектива, упакуйте сеанс в ZIP командой `multiai export <sessionId>` или экспортируйте удобную для чтения историю Markdown командой `/export-md` в TUI.
