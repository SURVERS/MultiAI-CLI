# OAuth и учётная запись

MultiAI CLI выполняет вход как публичный нативный OAuth-клиент: у него есть `client_id`, но нет секрета клиента. Для входа через браузер используется Authorization Code с PKCE (одноразовым подтверждением, которое создаёт клиент), а вход с устройства доступен, когда обратный вызов через браузер на локальный адрес использовать неудобно.

## Настройка приложения в multiai.store

Создайте в `multiai.store` одно OAuth-приложение с точно такими значениями:

| Параметр | Значение |
| --- | --- |
| Название | `MultiAI CLI` |
| Тип приложения | На устройстве — IDE, CLI или приложение |
| URI перенаправления | `http://127.0.0.1:1/oauth/callback` |
| Разрешения | Вход, профиль, электронная почта, баланс и лимиты, список ключей API, доступ к моделям |
| Авторизация устройства | Включена |
| Секрет клиента | Не создавать и не использовать |

Зарегистрируйте только указанный выше локальный IPv4-адрес. Не добавляйте `localhost` или обратный вызов по IPv6. Во время работы CLI слушает динамический порт на `127.0.0.1`; зарегистрированный URI с портом `1` обозначает схему нативного обратного вызова на локальный адрес, которую ожидает MultiAI.

После создания приложения скопируйте его публичный `client_id`. Это значение встроено в рабочие сборки. В сборках для разработки и тестовой среды его можно переопределить:

```sh
MULTIAI_OAUTH_CLIENT_ID=YOUR_PUBLIC_CLIENT_ID multiai login
```

Провайдер авторизации по умолчанию — `https://multiai.store`; переменная `MULTIAI_OAUTH_ISSUER` предназначена только для контролируемых сред разработки или тестирования.

## Вход и просмотр учётной записи

По умолчанию вход выполняется через браузер. CLI запускает временный обработчик на локальном адресе, открывает страницу авторизации, проверяет обратный вызов и закрывает обработчик:

```sh
multiai login
```

Если обратный вызов не может достичь терминала, используйте поток авторизации устройства и подтвердите показанный код в браузере:

```sh
multiai login --device
```

Оба способа запрашивают `openid profile email account:read keys:read ai:invoke`. В TUI им соответствуют команды `/login`, `/login --device` и `/login --session-only`. В веб-интерфейсе и VS Code доступны те же варианты: через браузер, с устройства и только на время сеанса.

Показать текущий профиль, баланс кошелька и его составляющие, состояние подписки, квоты использования, предоставленные области доступа, сведения о подключении и замаскированные ключи API можно командами:

```sh
multiai account
multiai profile
multiai account --json
```

`multiai profile` — псевдоним `multiai account`. Для панели профиля в TUI используйте `/account` или `/profile`; там также показано использование токенов и окна контекста в текущем сеансе. Квоты подписки отображаются, если они присутствуют в снимке состояния учётной записи.

## Идентификация и изменения профиля

Постоянный идентификатор учётной записи — пара OpenID Connect `(iss, sub)` (провайдер и субъект). Электронная почта, отображаемое имя, аватар и Telegram — атрибуты профиля, а не идентификаторы.

MultiAI CLI обновляет данные из `/oauth/userinfo` после входа и каждого обновления токена. Панели учётной записи загружают кошелёк, лимиты, сведения о подключении и замаскированные ключи из `/api/oauth/v1/snapshot`. Поэтому после изменения электронной почты, имени, аватара или Telegram сеанс остаётся активным, а при следующем обновлении отображаются новые данные. CLI не хранит Telegram. Если сервер назначит другой `sub`, CLI сочтёт его другой учётной записью.

## Хранение токенов и режим только на время сеанса

Токен обновления хранится через системное хранилище ключей: Диспетчер учётных данных Windows, Связку ключей macOS или Secret Service в Linux. Токены доступа, утверждения ID-токена, профили и снимки состояния учётной записи остаются в памяти процесса. MultiAI CLI никогда не записывает OAuth-токены в обычный текстовый файл.

Если системное хранилище ключей недоступно, интерактивные клиенты могут предложить сеанс, существующий только в текущем процессе. В неинтерактивном терминале включите его явно:

```sh
multiai login --session-only
multiai login --device --session-only
```

Такой сеанс завершается вместе с процессом. При первом запуске MultiAI CLI удаляет только распознанный устаревший файл учётных данных `~/.kimi-code/credentials/kimi-code.json`, не затрагивая остальное содержимое `~/.kimi-code`.

## Истечение срока, отзыв и состояние учётной записи

Истечение срока токена доступа обычно незаметно: выполняется одно синхронизированное обновление, после чего неудавшийся запрос повторяется один раз. Срок токенов обновления истекает через 30 дней бездействия или через 90 дней общего времени жизни; после этого требуется новый интерактивный вход.

Следующие условия очищают локальный сеанс, удаляют модели `managed:multiai` и возвращают клиент в обычное состояние без входа:

- учётная запись удалена, заблокирована или недоступна по другой причине;
- подключение отозвано, пароль сброшен или MFA отключена;
- OAuth-клиент архивирован;
- ротация токенов неоднозначна, возвращает `invalid_grant` или не может быть безопасно зафиксирована;
- обновлённый токен идентификации не проходит проверку подписи или утверждений.

При выходе сначала предпринимается попытка отозвать токен обновления, а затем локальный сеанс и управляемая конфигурация очищаются в любом случае, даже если провайдер авторизации недоступен:

```sh
multiai logout
```

## Баланс, области доступа и ограничения частоты запросов

Ответ HTTP `402 insufficient_quota` означает, что баланс MultiAI исчерпан. Клиент сохраняет вход в учётную запись, не обновляет токен и предлагает пользователю пополнить счёт на `https://multiai.store/account`.

Ответ `insufficient_scope` также не завершает сеанс. Обновите разрешения OAuth-приложения в `multiai.store`: повторный вход не может предоставить разрешение, которое не запрашивает само приложение. При HTTP `429` клиент соблюдает `Retry-After` и не превращает ограничение частоты запросов в выход из учётной записи.

## Проверки безопасности

MultiAI CLI загружает метаданные OAuth до авторизации и отклоняет конечные точки авторизации, токенов, устройства, отзыва, сведений о пользователе или JWKS, если они находятся на другом источнике. ID-токены должны использовать RS256 и проходить проверки `kid`, подписи JWKS, `iss`, `aud`, `exp`, `iat`, `nonce` и типов утверждений с допустимым расхождением часов в 60 секунд.

URL обратного вызова, коды авторизации, средства проверки PKCE, коды устройства и пользователя, а также значения, начинающиеся с `ma-oauth-`, скрываются в диагностических журналах.

## Модели после входа

После аутентификации MultiAI CLI загружает `/v1/models` и создаёт псевдонимы вида `multiai/<model-id>`. Модели генерации изображений, соответствующие GPT Image или Nano Banana, модели транскрибирования, соответствующие GPT Transcribe, и внутренние псевдонимы `ma-` исключаются, поскольку среда выполнения агента CLI не поддерживает их как чат-модели. В каталоге могут отсутствовать длина контекста и другие возможности; отсутствующие значения остаются неизвестными и не угадываются. Запросы к остальным псевдонимам используют OpenAI-совместимую конечную точку `/v1/responses`.
