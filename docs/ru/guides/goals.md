# Цели

Цели помогают MultiAI CLI двигаться к заданному результату на протяжении нескольких ходов. Обычный запрос говорит, что делать дальше, а цель — что должно стать истинным. Используйте `/goal`, когда у задачи есть чёткий конечный результат, но следующий полезный шаг зависит от того, что агент узнает в процессе, — например, при исправлении набора неработающих тестов или поиске первопричины сломанной сборки.

## Создание цели

Укажите задачу после `/goal`:

```sh
/goal Исправь ошибки, перечисленные в трекере задач.
```

MultiAI CLI сохраняет задачу, отправляет её как следующее сообщение пользователя и запускает режим цели. После каждого хода он проверяет, завершена, заблокирована или приостановлена цель либо работа над ней всё ещё продолжается.

Лучше всего цели работают, когда в задаче указаны конечный результат и подтверждающие его доказательства:

```sh
/goal Исправь все ошибки с меткой checkout-regression, добавь или обнови тесты для каждого исправления и запусти набор тестов checkout
```

Избегайте целей, задающих лишь общее направление:

```sh
/goal Найди все ошибки в этой кодовой базе.
```

Такая цель не определяет критерии успеха, область проверки и условие остановки. Агент может сразу заблокировать её или работать гораздо дольше, чем вы ожидали.

### Когда использовать цели

1. Используйте цели для работы с чётким результатом и проверяемыми доказательствами.

    ```sh
    /goal Исправь все неработающие тесты checkout и добейся успешного прохождения набора тестов checkout.
    ```

    MultiAI CLI может изучать вывод тестов, изменять файлы, повторно запускать проверки и определять, когда цель достигнута.

2. Используйте цели, если для исследования и исправления может потребоваться несколько ходов.

    ```sh
    /goal Выясни, почему не проходит релизная сборка, устрани первопричину и проверь успешность сборки.
    ```

    Цель описывает результат, поэтому агент может адаптироваться, если первая зацепка окажется не первопричиной.

3. Используйте цели для последовательной работы, которая должна продолжаться без нового запроса.

    ```sh
    /goal Обнови реализацию функции, добавь документацию, запусти тесты и перечисли изменённые файлы.
    ```

    Это удобно, когда вы заранее знаете, какие проверки должны пройти или какие материалы должны появиться до завершения работы.

### Когда не стоит использовать цели

1. Не используйте цели для общих тем или обсуждений без определённого результата.

    ::: warning Контрпример
    ```sh
    /goal Привет!
    ```
    :::

    Если запрос не является целью, агенты сразу пометят её завершённой.

2. Не используйте цели для заведомо невозможных или неразрешимых задач.

    ::: warning Контрпример
    ```sh
    /goal Докажи, что 1 + 1 = 3.
    ```
    :::

    Если цель кажется невозможной или неразрешимой, агенты пометят её заблокированной.

3. Не используйте неоднозначные или слишком сложные формулировки.

    ::: warning Контрпример
    ```sh
    /goal Создай видеоигру в одном HTML-файле.
    ```
    :::

    Агенты могут выполнить такую цель, но после долгой работы результат может оказаться неожиданным.

## Управление жизненным циклом

Текущее состояние цели можно просматривать и изменять теми же командами:

| Команда | Действие |
| --- | --- |
| `/goal` или `/goal status` | Показать текущую цель и ход работы |
| `/goal pause` | Приостановить активную цель, не удаляя её |
| `/goal resume` | Возобновить приостановленную или заблокированную цель |
| `/goal cancel` | Удалить текущую цель |
| `/goal replace <objective>` | Заменить текущую цель новой задачей |

Работа над целью может остановиться тремя способами:

- **завершена**: задача выполнена, MultiAI CLI очищает цель, а агент кратко описывает проделанную работу;
- **приостановлена**: вы приостановили её, прервали ход, возобновили сеанс с активной целью либо произошла ошибка модели, провайдера или среды выполнения;
- **заблокирована**: MultiAI CLI нужны дополнительные данные, цель нельзя выполнить в указанном виде или достигнут предел бюджета. При блокировке агент кратко объясняет причину.

Указывайте условия остановки прямо в задаче. У `/goal` нет отдельного параметра ограничения остановки.

## Управление целями в веб-интерфейсе

Текущая цель отображается в веб-интерфейсе на полосе под беседой. Нажмите на неё, чтобы развернуть или свернуть подробности. Если настроен бюджет токенов, в заголовке показывается ход его расходования; без бюджета индикатор не отображается.

Кнопки на полосе позволяют приостановить активную цель, возобновить приостановленную или заблокированную либо отменить текущую. При выборе Resume начинается следующий ход по цели. Отмена требует подтверждения, поскольку после неё возобновить цель нельзя.

## Очередь следующих целей

Иногда агенты завершают цель слишком быстро. Пользователей может расстраивать возможность назначить только одну цель за раз. Многие заранее знают, какие цели будут следующими, но раньше им приходилось ждать завершения текущей цели, открывать TUI и вручную отправлять следующую.

Используйте `/goal next`, если следующая работа уже известна, но прерывать текущую цель не нужно:

```sh
/goal next Обнови примечания к выпуску после прохождения тестов
```

Пока выполняется текущая цель, агент не видит следующие. После её завершения MultiAI CLI запускает первую цель из очереди так же, как при вводе `/goal <objective>`.

Если активной цели нет, `/goal next <objective>` запускает задачу сразу. Команда работает как `/goal <objective>` и перед запуском показывает сообщение о состоянии.

Для интерактивного управления следующими целями выполните:

```sh
/goal next manage
```

В диспетчере используйте <kbd>↑</kbd> / <kbd>↓</kbd> для навигации, <kbd>Space</kbd> для выбора перемещаемой цели, <kbd>↑</kbd> / <kbd>↓</kbd> для изменения её порядка, <kbd>E</kbd> для редактирования, <kbd>D</kbd> для удаления и <kbd>Esc</kbd> для отмены. При редактировании добавляйте новую строку через <kbd>Shift-Enter</kbd> или <kbd>Ctrl-J</kbd>, а сохраняйте через <kbd>Enter</kbd>.

Если текущая цель приостановлена, отменена или заблокирована, MultiAI CLI не запускает следующую. Когда цель заблокирована, а очередь не пуста, TUI напоминает, что следующие цели ждут её завершения.

## Используйте режим цели осмотрительно

Режим цели полезен для работы, которую можно проверить по файлам, тестам, выводу команд, созданным материалам или чёткому письменному отчёту. Для разового изменения или вопроса с одним ответом он подходит хуже.

В режиме разрешений `manual` работа над целью может приостанавливаться для подтверждения вызовов инструментов. Для автономной работы выберите режим разрешений, соответствующий рискам репозитория и командам, которые может выполнять агент.

В неинтерактивном режиме запросов поддерживается только создание цели:

```sh
multiai -p "/goal Исправь неработающий тест checkout"
```

Режим запросов завершается с кодом `0`, если цель достигнута, `3`, если она заблокирована, и `6`, если приостановлена. `/goal next` и другие команды управления предназначены для TUI.
