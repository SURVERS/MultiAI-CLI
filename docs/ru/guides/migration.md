# Устаревшие данные

MultiAI CLI начинает работу с новым названием продукта, командой, пространством имён пакетов и домашним каталогом. Настройки и история из Kimi Code или `kimi-cli` не импортируются.

::: warning Удалено
В MultiAI CLI 1.0.0 не входят прежнее рабочее пространство миграции и команда `migrate`.
:::

## Что использует MultiAI CLI

Новые данные записываются только в расположения MultiAI:

- глобальные данные и конфигурация: `~/.multiai`;
- конфигурация рабочего пространства: `.multiai/local.toml`;
- команда: `multiai`;
- переменные окружения: `MULTIAI_*`.

Прежняя команда `kimi`, пути `~/.kimi-code` и `.kimi-code/local.toml`, а также настройки продукта `KIMI_*` не являются псевдонимами и не считываются.

## Очистка устаревших учётных данных

При первом запуске MultiAI CLI проверяет только `~/.kimi-code/credentials/kimi-code.json`. Если он распознан как прежний файл управляемых учётных данных OAuth, файл удаляется, чтобы не оставлять устаревший токен в открытом виде.

Никакие другие файлы и каталоги в `~/.kimi-code` не изменяются. Убедившись, что старое приложение вам больше не нужно, самостоятельно сохраните, архивируйте или удалите этот каталог.

## Настройка MultiAI

Установите MultiAI CLI, а затем войдите как новый нативный OAuth-клиент:

```sh
multiai login
```

Заново настройте пользовательские провайдеры и локальные плагины в `~/.multiai`. MultiAI по-прежнему поддерживает внешнего провайдера моделей Kimi, но этот провайдер не связан с удалённой учётной записью продукта Kimi и процессом миграции. Настройка учётной записи и поведение токенов описаны в разделе [OAuth и учётная запись](./account-and-oauth.md).
