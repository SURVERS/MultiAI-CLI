# Сеансы и контекст

MultiAI CLI сохраняет каждую беседу как «сеанс» — историю сообщений и метаданные, благодаря которым можно закрыть терминал и продолжить с того же места. На этой странице описано, как возобновлять сеансы, управлять контекстом, экспортировать сеансы и создавать их ответвления.

## Хранение сеансов

Все сеансы сохраняются в `$MULTIAI_HOME/sessions/` (по умолчанию `~/.multiai/sessions/`) и группируются по рабочим каталогам:

```text
~/.multiai/
├── config.toml
├── session_index.jsonl
└── sessions/
    └── <workDirKey>/
        └── <sessionId>/
            ├── state.json
            └── agents/
                ├── main/
                │   └── wire.jsonl
                └── <subagentId>/
                    └── wire.jsonl
```

- `state.json`: метаданные сеанса, например название и время создания.
- `agents/*/wire.jsonl`: поток событий агента для восстановления и повторного воспроизведения сеанса. Он также содержит трассировку запроса — схемы инструментов, параметры запроса и списки инструментов MCP, переданные модели, — для отладки.

::: warning
Не редактируйте файлы в каталоге `sessions/` вручную: это может помешать правильному восстановлению сеансов.
:::

## Создание и возобновление сеансов

При каждом прямом запуске `multiai` создаётся новый сеанс. Возобновить предыдущий сеанс можно одним из следующих способов.

**Возобновить последний сеанс в текущем каталоге:**

```sh
multiai --continue
```

**Возобновить определённый сеанс по идентификатору:**

```sh
multiai --session abc123
```

**Просмотреть историю сеансов в интерактивном режиме и выбрать нужный:**

```sh
multiai --session
```

::: warning
Параметры `--continue` и `--session` взаимоисключающие.
:::

## Переключение сеансов в TUI

Сеансами можно управлять, не покидая терминал. Следующие команды с косой чертой доступны только во время ожидания агента:

- **`/new`** (псевдоним `/clear`): перейти к новому сеансу, отбросив текущий контекст.
- **`/sessions`** (псевдоним `/resume`): просмотреть и возобновить предыдущий сеанс.
- **`/fork`**: создать ответвление текущего сеанса (см. ниже).
- **`/title <text>`** (псевдоним `/rename`): задать название сеанса для удобства поиска; без аргументов показывает текущее название.

## Сжатие контекста

По мере роста беседы MultiAI CLI автоматически сжимает историю сообщений, когда контекст приближается к пределу окна, освобождая место для токенов. Сжатие также можно запустить вручную в любой момент:

```
/compact
```

Можно добавить подсказку, чтобы указать модели, чему отдать приоритет при сжатии:

```
/compact Сохрани обсуждение миграций базы данных
```

## Ответвление сеанса

Чтобы исследовать новое направление, не нарушая текущую беседу, используйте `/fork`:

```
/fork
```

Два получившихся сеанса полностью независимы и не влияют друг на друга. Вернуться к исходному можно в любой момент через `/sessions`. Сохранённая `/goal` не копируется в ответвление. Если в нём нужна автономная работа над целью, создайте новую цель.

## Экспорт сеанса

Команда `multiai export` упаковывает сеанс в ZIP-файл, что удобно для передачи, архивации или отчёта об ошибке:

```sh
multiai export <sessionId>
```

Если `sessionId` не указан, экспортируется последний сеанс в текущем каталоге с интерактивным подтверждением; добавьте `-y`, чтобы его пропустить. Путь вывода задаётся через `-o`:

```sh
multiai export <sessionId> -o ~/Desktop/my-session.zip
```

В экспорт входят все файлы каталога сеанса, включая диагностические журналы. Глобальный диагностический журнал (`~/.multiai/logs/multiai.log`) также добавляется по умолчанию; исключить его можно параметром `--no-include-global-log`.

Экспортировать данные можно и из TUI, не завершая интерактивный сеанс:

- **`/export-debug-zip`**: создаёт тот же отладочный ZIP, что и `multiai export`.
- **`/export-md`** (псевдоним `/export`): экспортирует беседу в удобный для чтения файл Markdown для передачи или архивации. Принимает необязательный путь; без него записывает файл `multiai-export-<short-id>-<timestamp>.md` в текущий рабочий каталог.

В веб-интерфейсе `/export` скачивает текущий сеанс как диагностический ZIP. В него входят сохранённые данные сеанса, диагностические журналы и ограниченная запись `logs/multiai-web.jsonl`, содержащая только метаданные ключевых событий браузера. Текст запросов, полезная нагрузка WebSocket и аргументы консоли в этот браузерный журнал не копируются. Эта веб-команда отличается от описанного выше псевдонима `/export` в TUI.

Перед сохранением браузер буферизует ZIP, поэтому размер веб-экспорта ограничен 64 МиБ. Для более крупного сеанса используйте `multiai export <sessionId>` или команду TUI `/export-debug-zip`.

::: tip
Экспортированные файлы могут содержать конфиденциальные код, вывод команд и пути. Проверьте содержимое перед передачей.
:::
