# Переопределение конфигурации

На рабочие параметры MultiAI CLI можно влиять тремя способами: через файл конфигурации, параметры командной строки и переменные окружения. Их отношения не сводятся к простому правилу «побеждает источник с наивысшим приоритетом»: они предназначены для разных сценариев и почти не пересекаются по области действия.

- **Файл конфигурации** хранит долгосрочные настройки (модель, ключи, управление циклом и т. д.) и применяется при каждом запуске.
- **Параметры командной строки** вносят разовые изменения для текущего запуска и отбрасываются после выхода.
- **Переменные окружения** в основном задают расположение каталога данных, переключают конечные точки OAuth и управляют небольшим числом рабочих переключателей — это **не универсальный механизм резервных значений для полей конфигурации**.

Это различие важно: многие выполняют в оболочке `export KIMI_API_KEY=xxx`, ожидая, что CLI автоматически подхватит ключ, но этого не происходит. Причина описана ниже в разделе [Учётные данные провайдеров](#provider-credentials).

## Три роли переменных окружения

По назначению переменные окружения делятся на три категории, которые нельзя выстроить в одну линейную очередь приоритетов:

1. **Определение расположения файла конфигурации**: `MULTIAI_HOME` задаёт корневой каталог данных, поэтому путь к файлу становится `$MULTIAI_HOME/config.toml`. Этот шаг выполняется до разрешения остальных значений и не предоставляет резервные значения отдельным параметрам.
2. **Рабочие переключатели**: небольшая группа переменных вроде `MULTIAI_DISABLE_TELEMETRY` напрямую отключает соответствующую подсистему. Даже если в `config.toml` указано `telemetry = true`, истинное значение этой переменной отключит телеметрию. Здесь действует правило «дополнительно отключить», а не обычное переопределение.
3. **Рабочие конечные точки и диагностика**: переменные вроде `MULTIAI_OAUTH_HOST`, `MULTIAI_BASE_URL` и `MULTIAI_LOG_LEVEL` читаются при инициализации подсистем OAuth или журналирования. Полный список см. в разделе [Переменные окружения](./env-vars.md).

## Приоритет обычных рабочих параметров

Для обычных параметров, таких как псевдоним модели, Plan mode, YOLO mode и каталоги Skills, приоритет от высшего к низшему таков:

1. **Параметры командной строки** (`-m`, `--plan`, `--yolo` и т. д.): действуют только при текущем запуске.
2. **Пользовательский файл конфигурации** (`~/.multiai/config.toml`): хранит долгосрочные настройки.

Небольшое число переменных окружения явно переопределяет отдельные поля файла конфигурации. Например, `MULTIAI_BACKGROUND_KEEP_ALIVE_ON_EXIT` имеет приоритет над `[background].keep_alive_on_exit`. Такие исключения отмечены в разделах [Переменные окружения](./env-vars.md) и [Файлы конфигурации](./config-files.md).

::: warning Внимание
**Обычные рабочие параметры не получают резервные значения из переменных окружения оболочки.** Поля провайдера `api_key` / `base_url` читаются только из `config.toml` (включая подраздел `[providers.<name>.env]`) и не берутся из переменных, заданных через `export`. Единственное исключение — явный канал `MULTIAI_MODEL_*`; см. [Определение модели через переменные окружения](./env-vars.md#define-a-model-from-environment-variables-kimi-model).
:::

Сейчас CLI читает один пользовательский файл конфигурации и не поддерживает файл конфигурации уровня проекта. Чтобы изолировать конфигурации разных проектов, направляйте `MULTIAI_HOME` в разные каталоги данных; примеры приведены в разделе [Распространённые сценарии](#common-scenarios).

## Учётные данные провайдеров

Учётные данные провайдера (`api_key`, `base_url`) разрешаются по собственным правилам, отдельно от обычной цепочки приоритетов.

Для одного провайдера учётные данные разрешаются в следующем порядке:

1. `[providers.<name>].api_key` — ключ, записанный непосредственно в файле конфигурации; наивысший приоритет.
2. Соответствующий ключ в подразделе `[providers.<name>.env]` (`KIMI_API_KEY`, `ANTHROPIC_API_KEY` и т. д.) — используется только при пустом `api_key`.
3. Если нет обоих значений, запуск завершается ошибкой об отсутствии учётных данных провайдера.

`base_url` разрешается так же: сначала `[providers.<name>].base_url`, затем ключ `*_BASE_URL` в `[providers.<name>.env]`.

> Подраздел `[providers.<name>.env]` — обычная секция TOML в файле конфигурации. Он ничего не записывает в окружение оболочки и используется лишь тогда, когда соответствующее прямое поле (`api_key` / `base_url`) пусто.

Полный список имён ключей см. в разделе [Переменные окружения: имена ключей учётных данных провайдеров](./env-vars.md#provider-credential-key-names-written-in-configtoml).

## Параметры командной строки

Параметры запуска имеют наивысший приоритет и действуют только в текущем сеансе:

| Параметр | Действие |
| --- | --- |
| `-S, --session [id]` | Возобновить указанный сеанс; без идентификатора открыть интерактивный выбор |
| `-c, --continue` | Возобновить последний сеанс текущего рабочего каталога |
| `-y, --yolo` | Автоматически подтверждать обычные вызовы инструментов; агент всё ещё может задавать вопросы |
| `--auto` | Запустить режим автоматических разрешений: полная автономность без вопросов агента |
| `--plan` | Запустить Plan mode |
| `-m, --model <model>` | Использовать в этом сеансе указанный псевдоним модели |
| `-p, --prompt <prompt>` | Запустить неинтерактивный режим: выполнить один запрос и выйти |
| `--output-format <format>` | Формат вывода режима `-p`: `text` или `stream-json` |
| `--skills-dir <dir>` | Заменить автоматически найденные каталоги Skills (можно указывать несколько раз; только для текущего сеанса) |

Правила взаимного исключения (при нарушении запуск завершается ошибкой):

- `--output-format` можно использовать только с `-p`.
- `--prompt` нельзя сочетать с `--yolo` или `--plan`.
- `--continue` и `--session` нельзя использовать вместе.
- В режиме без запроса `--yolo` и `--plan` нельзя сочетать с `--continue` или `--session`.

::: tip Совет
`--skills-dir` — разовая замена только для текущего запуска. Чтобы постоянно добавлять каталоги поиска, укажите `extra_skill_dirs` в `config.toml` (см. [Agent Skills](../customization/skills.md)).
:::

## Распространённые сценарии

**Изолированное тестовое окружение** — используйте отдельный каталог данных, чтобы не засорять основную конфигурацию и сеансы:

```sh
MULTIAI_HOME="$PWD/.multiai-sandbox" multiai
```

**Разовый тестовый ключ** — поскольку учётные данные провайдера читаются только из файла конфигурации, запишите тестовый ключ в подраздел `env`:

```toml
[providers.kimi.env]
KIMI_API_KEY = "sk-test"
```

**Не запрашивать подтверждения для пакетных задач**:

```sh
multiai --yolo -p "Batch rename the following files..."
```

**Временно включить Plan mode** (чтобы сделать это постоянной настройкой, задайте в файле конфигурации `default_plan_mode = true`):

```sh
multiai --plan
```
