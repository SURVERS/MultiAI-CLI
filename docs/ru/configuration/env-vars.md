# Переменные окружения

MultiAI CLI использует переменные окружения для управления небольшим числом параметров времени выполнения: переноса каталога данных, отключения телеметрии и временного переключения моделей без изменения файла конфигурации.

::: warning Важно: ключи API здесь не настраиваются
Переменные с учётными данными, такие как `KIMI_API_KEY`, `ANTHROPIC_API_KEY` и `OPENAI_API_KEY`, **не считываются** автоматически из окружения оболочки. Команда `export KIMI_API_KEY=xxx` в терминале не передаёт ключ ни одному провайдеру — ключ нужно записать в `config.toml` в секции `[providers.<name>]` или вложенной таблице `[providers.<name>.env]`.

Единственное исключение — семейство `MULTIAI_MODEL_*`: это отдельный механизм, который действительно считывает учётные данные из оболочки. См. [Определение модели через переменные окружения](#определение-модели-через-переменные-окружения-multiai-model).

Подробнее см. в разделе [Переопределение конфигурации: учётные данные провайдера](./overrides.md#provider-credentials).
:::

## Основные пути

### `MULTIAI_HOME`

Переопределяет корневой каталог данных; по умолчанию используется `~/.multiai`. После установки переменной файл конфигурации, сеансы, журналы, учётные данные OAuth и все остальные данные сохраняются по новому пути:

```sh
export MULTIAI_HOME="/path/to/custom/multiai"
```

> Убедись, что каталог доступен для записи. Несколько экземпляров `multiai` с одним и тем же `MULTIAI_HOME` будут совместно использовать файлы конфигурации и учётных данных.

Полную структуру каталога см. в разделе [Расположение данных](./data-locations.md).

### `MULTIAI_DISABLE_TELEMETRY`

Установи значение `1`, чтобы отключить отправку анонимной телеметрии (также принимаются `true`, `yes` и `y` без учёта регистра):

```sh
export MULTIAI_DISABLE_TELEMETRY=1
```

### Семейство `MULTIAI_MODEL_*`

Позволяет временно переключить модель без изменения `config.toml`: если задана `MULTIAI_MODEL_NAME`, CLI создаёт временный провайдер в памяти. После перезапуска изменение исчезает. См. [Определение модели через переменные окружения](#определение-модели-через-переменные-окружения-multiai-model).

## Имена ключей учётных данных провайдеров (записываются в config.toml)

Приведённые ниже ключи не считываются напрямую из оболочки. Это имена ключей внутри вложенной таблицы `[providers.<name>.env]` файла `config.toml`, которые служат резервными значениями для `api_key` и `base_url`. CLI читает их только из файла конфигурации, а не из `process.env`.

Так можно сохранить привычные имена ключей и при этом централизованно хранить секреты в файле конфигурации:

```toml
[providers.kimi.env]
KIMI_API_KEY = "sk-xxx"
KIMI_BASE_URL = "https://api.moonshot.ai/v1"
```

Имена ключей для каждого провайдера:

| Ключ | Провайдер | Значение по умолчанию |
| --- | --- | --- |
| `KIMI_API_KEY` | Kimi / Moonshot | Нет |
| `KIMI_BASE_URL` | Kimi / Moonshot | `https://api.moonshot.ai/v1` |
| `ANTHROPIC_API_KEY` | Anthropic | Нет |
| `ANTHROPIC_BASE_URL` | Anthropic | Значение по умолчанию из Anthropic SDK |
| `OPENAI_API_KEY` | OpenAI (`openai` и `openai_responses`) | Нет |
| `OPENAI_BASE_URL` | OpenAI (`openai` и `openai_responses`) | `https://api.openai.com/v1` |
| `GOOGLE_API_KEY` | Google GenAI, Vertex AI | Нет |
| `VERTEXAI_API_KEY` | Vertex AI | Нет |
| `GOOGLE_CLOUD_PROJECT` | Vertex AI | Нет |
| `GOOGLE_CLOUD_LOCATION` | Vertex AI | Нет |

::: warning
`GOOGLE_APPLICATION_CREDENTIALS` (путь к JSON-файлу сервисного аккаунта) — единственное исключение, которое обрабатывается через системные переменные окружения. Google SDK считывает её напрямую с помощью стандартного механизма ADC, а CLI в этом не участвует. Все остальные ключи нужно помещать во вложенную таблицу `[providers.<name>.env]`.
:::

Полное описание типов и полей провайдеров см. в разделе [Провайдеры и модели](./providers.md).

## OAuth и управляемые сервисы

Рабочий издатель OAuth — `https://multiai.store`. Нативные клиенты являются публичными и не должны использовать секрет клиента.

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `MULTIAI_OAUTH_CLIENT_ID` | Переопределение ID публичного нативного клиента для разработки или тестового окружения | Встроенное значение релиза |
| `MULTIAI_OAUTH_ISSUER` | Переопределение издателя OAuth для разработки или тестового окружения | `https://multiai.store` |

`MULTIAI_BASE_URL` по-прежнему переопределяет базовый URL вручную настроенного провайдера с Kimi-совместимым протоколом. Это не издатель OAuth.

## Определение модели через переменные окружения (`MULTIAI_MODEL_*`)

Чтобы протестировать другую модель без изменения `config.toml`, задай `MULTIAI_MODEL_NAME`. CLI создаст в памяти временный провайдер и псевдоним модели из переменных `MULTIAI_MODEL_*`; в файл конфигурации ничего не записывается. Эти переменные имеют приоритет над `default_model` в `config.toml`, но параметр запуска `-m <alias>` всё равно обладает наивысшим приоритетом.

```sh
export MULTIAI_MODEL_NAME="kimi-for-coding"
export MULTIAI_MODEL_API_KEY="YOUR_API_KEY"
export MULTIAI_MODEL_BASE_URL="https://api.example.com/v1"
export MULTIAI_MODEL_MAX_CONTEXT_SIZE="262144"
export MULTIAI_MODEL_CAPABILITIES="image_in,thinking"
multiai
```

Полный список переменных:

| Переменная | Обязательна | Назначение | По умолчанию |
| --- | --- | --- | --- |
| `MULTIAI_MODEL_NAME` | Да (также включает механизм) | ID модели, отправляемый API | — |
| `MULTIAI_MODEL_API_KEY` | Да | Ключ API | — |
| `MULTIAI_MODEL_PROVIDER_TYPE` | Нет | Тип провайдера: `kimi`, `anthropic`, `openai` | `kimi` |
| `MULTIAI_MODEL_BASE_URL` | Нет | Базовый URL API | Зависит от типа |
| `MULTIAI_MODEL_MAX_CONTEXT_SIZE` | Нет | Максимальный размер контекста в токенах | `262144` (256 КБ) |
| `MULTIAI_MODEL_CAPABILITIES` | Нет | Разделённые запятыми возможности, объединяемые с определёнными автоматически | `image_in,thinking` |
| `MULTIAI_MODEL_DISPLAY_NAME` | Нет | Имя в `/model` | `MULTIAI_MODEL_NAME` |
| `MULTIAI_MODEL_MAX_OUTPUT_SIZE` | Нет | Ограничение вывода на запрос (только `anthropic`); переопределяет встроенный предел Claude | Значение модели |
| `MULTIAI_MODEL_REASONING_KEY` | Нет | Переопределение имени поля рассуждений (только `openai`) | Определяется автоматически |
| `MULTIAI_MODEL_THINKING_EFFORT` | Нет | Уровень усилий Thinking mode: `low`/`medium`/`high`/`xhigh`/`max` | — |
| `MULTIAI_MODEL_ADAPTIVE_THINKING` | Нет | Принудительно включить или выключить адаптивное мышление (только `anthropic`) | Определяется по имени модели |

Если `MULTIAI_MODEL_NAME` задана, но обязательная переменная отсутствует, запуск сразу завершится с понятным сообщением об ошибке.

## Переключатели времени выполнения

Эти переменные управляют телеметрией, фоновыми задачами, магазином плагинов и другими подсистемами:

| Переменная | Назначение | Допустимые значения |
| --- | --- | --- |
| `MULTIAI_DISABLE_TELEMETRY` | Отключить анонимную телеметрию | `1`, `true`, `yes`, `y` без учёта регистра |
| `MULTIAI_BACKGROUND_KEEP_ALIVE_ON_EXIT` | Сохранять фоновые задачи после закрытия сеанса; приоритет выше `config.toml`. По умолчанию задачи останавливаются | Истина: `1`/`true`/`yes`/`on`; ложь: `0`/`false`/`no`/`off` |
| `MULTIAI_BACKGROUND_MAX_RUNNING_TASKS` | Максимум одновременно выполняемых фоновых задач; приоритет выше `[background] max_running_tasks` | Положительное целое; неверные значения игнорируются |
| `MULTIAI_IMAGE_MAX_EDGE_PX` | Максимальная длина стороны изображения при сжатии; приоритет выше `[image] max_edge_px` (по умолчанию `2000`) | Положительное целое; неверные значения игнорируются |
| `MULTIAI_IMAGE_READ_BYTE_BUDGET` | Лимит байтов на изображение при чтении моделью (`ReadMediaFile` по умолчанию); приоритет выше `[image] read_byte_budget` (по умолчанию `262144`, то есть 256 КБ) | Положительное целое; неверные значения игнорируются |
| `MULTIAI_PLUGIN_MARKETPLACE_URL` | Подключить пользовательский JSON магазина плагинов для `/plugins` | По умолчанию магазина нет; поддерживаются `https://`, `http://`, `file://` и локальный путь |
| `MULTIAI_AGENT_SWARM_MAX_CONCURRENCY` | Ограничить число одновременно запускаемых субагентов AgentSwarm | Положительное целое; неверное значение немедленно вызывает ошибку |
| `MULTIAI_SUBAGENT_TIMEOUT_MS` | Максимальное время работы одного субагента (`Agent` / `AgentSwarm`) в мс; приоритет выше `[subagent] timeout_ms` (по умолчанию `7200000`, 2 часа) | Положительное целое; при ошибке используется конфигурация или значение по умолчанию |
| `MULTIAI_EXPERIMENTAL_SECONDARY_MODEL` | Включить экспериментальную вторичную модель в `multiai web`; для движка v2 в `multiai -p` всё равно нужна `MULTIAI_EXPERIMENTAL_FLAG=1`, которая также включает эту функцию | Истина: `1`/`true`/`yes`/`on`; ложь: `0`/`false`/`no`/`off` |
| `MULTIAI_SECONDARY_MODEL` | Вторичная модель; приоритет выше `[secondary_model] model`. При включённом эксперименте новые субагенты по умолчанию используют её вместо модели основного агента (в TUI не поддерживается) | ID из `[models]`, например `multiai/kimi-k2.5`; пустые значения игнорируются |
| `MULTIAI_SECONDARY_EFFORT` | Усилия Thinking mode вторичной модели; приоритет выше `[secondary_model] default_effort`, действует только при включённых модели и эксперименте (в TUI не поддерживается) | Например `low`; пустые значения игнорируются |
| `MULTIAI_MCP_STARTUP_TIMEOUT_MS` | Общий тайм-аут подключения ко всем MCP-серверам; приоритет выше `[mcp] startup_timeout_ms`, но ниже `startupTimeoutMs` конкретного сервера в `mcp.json` (по умолчанию `30000`) | Целое от `1` до `2147483647`; неверные значения игнорируются |
| `MULTIAI_MCP_TOOL_TIMEOUT_MS` | Общий тайм-аут одного вызова инструмента MCP; приоритет выше `[mcp] tool_timeout_ms`, но ниже `toolTimeoutMs` сервера (по умолчанию `60000`) | Целое от `1` до `2147483647`; неверные значения игнорируются |
| `MULTIAI_LOOP_MAX_STEPS_PER_TURN` | Максимум шагов агента за ход; приоритет выше `[loop_control] max_steps_per_turn`; отсутствие или `0` снимает ограничение | Неотрицательное целое; неверные значения игнорируются |
| `MULTIAI_LOOP_MAX_RETRIES_PER_STEP` | Максимум повторов после ошибки шага; приоритет выше `[loop_control] max_retries_per_step` (по умолчанию `10`) | Неотрицательное целое; неверные значения игнорируются |
| `MULTIAI_WEB_SEARCH_BASE_URL` | URL API сервиса `WebSearch`; приоритет выше `[services.moonshot_search] base_url`, включает сервис без секции конфигурации. Сохранённые учётные данные и заголовки на выбранный через окружение адрес не передаются | Непустая строка |
| `MULTIAI_WEB_SEARCH_API_KEY` | Ключ API сервиса `WebSearch`; заменяет настроенный ключ и учётные данные OAuth | Непустая строка |
| `MULTIAI_WEB_FETCH_BASE_URL` | URL API пользовательского сервиса `FetchURL`; приоритет выше `[services.moonshot_fetch] base_url`. Сохранённые учётные данные и заголовки не передаются | Непустая строка |
| `MULTIAI_WEB_FETCH_API_KEY` | Ключ API сервиса `FetchURL`; заменяет настроенный ключ и OAuth | Непустая строка |
| `MULTIAI_EXPERIMENTAL_FLAG` | Включить все зарегистрированные экспериментальные функции процесса | `1`, `true`, `yes`, `on` |
| `MULTIAI_SHELL_PATH` | Переопределить путь к Git Bash в Windows, если автоопределение не сработало | Абсолютный путь |
| `MULTIAI_MODEL_MAX_COMPLETION_TOKENS` | Жёсткий предел `max_completion_tokens` на шаг LLM; только для провайдера `multiai` | Положительное целое; `0` или меньше отключает ограничение |
| `MULTIAI_MODEL_TEMPERATURE` | Температура выборки для каждого запроса; только для `multiai`, независимо от `MULTIAI_MODEL_NAME` | Число, например `0.3` |
| `MULTIAI_MODEL_TOP_P` | `top_p` для nucleus sampling каждого запроса; только для `multiai` | Число, например `0.95` |
| `MULTIAI_MODEL_THINKING_EFFORT` | Принудительно отправить `thinking.effort`, не учитывая `support_efforts`; только для `multiai` и включённого Thinking mode | Например `max` |
| `MULTIAI_MODEL_THINKING_KEEP` | Передача сохранённых рассуждений: для `multiai` как `thinking.keep`, для `anthropic` как правка `context_management` `clear_thinking_20251015`; переопределяет `[thinking] keep`, применяется только при включённом Thinking mode | Например `all`; `false`/`0`/`no`/`off`/`none`/`null` отключают |
| `MULTIAI_NO_AUTO_UPDATE` | Полностью отключить предварительную проверку обновлений, фоновую установку и запрос. Устаревший псевдоним `MULTIAI_NO_AUTO_UPDATE` также поддерживается | `1`/`true`/`yes`/`on` |
| `MULTIAI_DISABLE_CRON` | Отключить планировщик (`CronCreate` отклоняет новые задания, существующие не запускаются) | `1` для отключения |

MultiAI CLI не отправляет телеметрию продукта. `MULTIAI_DISABLE_TELEMETRY` поддерживается для совместимости, но в точках входа релизной версии удалённая телеметрия отключена.

## Диагностические журналы

Эти переменные задают уровень журналирования и ротацию файлов; они считываются один раз при запуске процесса:

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `MULTIAI_LOG_LEVEL` | Уровень: `off`, `error`, `warn`, `info`, `debug` | `info` |
| `MULTIAI_LOG_GLOBAL_MAX_BYTES` | Максимальный размер глобального файла журнала | `6291456` (6 МБ) |
| `MULTIAI_LOG_GLOBAL_FILES` | Число сохраняемых глобальных файлов | `5` |
| `MULTIAI_LOG_SESSION_MAX_BYTES` | Максимальный размер файла журнала сеанса | `5242880` (5 МБ) |
| `MULTIAI_LOG_SESSION_FILES` | Число сохраняемых файлов сеанса | `3` |

## Системные переменные окружения

CLI также читает стандартные системные переменные для определения среды выполнения, но не изменяет их:

- `HOME`: путь данных по умолчанию;
- `VISUAL`, `EDITOR`: команда внешнего редактора (`VISUAL` имеет приоритет);
- `PATH`: поиск `rg`, `fd`, `fdfind`, `git` и других зависимостей; в Windows Git Bash ищется по каждому `git.exe` в `PATH`, включая прокси менеджеров пакетов вроде Scoop;
- `NO_COLOR`, `FORCE_COLOR`: управление цветным выводом по соглашению [no-color.org](https://no-color.org);
- `CI`: непустое значение, кроме `"0"`, отключает определение темы и включает тёмную;
- `TERM_PROGRAM`, `TERM`, `TMUX`: определение возможностей терминала и уведомлений;
- `DISPLAY`, `WAYLAND_DISPLAY`, `XDG_SESSION_TYPE`: определение графической сессии Linux для буфера обмена и изображений;
- `WSL_DISTRO_NAME`, `WSLENV`: определение WSL для моста буфера обмена через PowerShell;
- `LOCALAPPDATA`: резервный путь поиска Git Bash в Windows.

## HTTP-прокси

MultiAI CLI учитывает стандартные переменные прокси для всего исходящего трафика: API моделей, MCP-серверов, веб-инструментов, телеметрии, входа и проверки обновлений:

- `HTTP_PROXY` / `http_proxy`: прокси для `http://`;
- `HTTPS_PROXY` / `https_proxy`: прокси для `https://`;
- `ALL_PROXY` / `all_proxy`: резервный прокси, если переменная для схемы не задана; обычно здесь указывают SOCKS-прокси;
- `NO_PROXY` / `no_proxy`: разделённые запятыми хосты, обходящие прокси.

Поддерживаются HTTP(S)- и SOCKS-прокси. SOCKS определяется по схеме `socks5://`, `socks5h://`, `socks4://` или `socks://` (псевдоним `socks5://`) и обычно задаётся через `ALL_PROXY`, как в Clash и V2RayN. Для HTTP/HTTPS соответствующий HTTP(S)-прокси имеет приоритет над `ALL_PROXY`.

Прокси применяется только при наличии одной из переменных. Локальные адреса (`localhost`, `127.0.0.1`, `::1`) всегда обходят прокси, поэтому локальный MCP-сервер продолжит работать. Собственные внутренние хосты добавь в `NO_PROXY`.

Stdio MCP-серверы, запущенные как дочерние процессы Node.js, автоматически учитывают `HTTP_PROXY`, `HTTPS_PROXY` и `NO_PROXY`, если версия Node.js поддерживает `NODE_USE_ENV_PROXY` (Node ≥ 22.21 или ≥ 24.5). SOCKS-прокси применяется только к собственному трафику MultiAI CLI.
