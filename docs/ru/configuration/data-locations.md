# Расположение данных

MultiAI CLI хранит все рабочие данные — файл конфигурации, историю сеансов, учётные данные для входа и диагностические журналы — в `~/.multiai/`. На этой странице описано, где находятся разные типы данных, зачем они нужны и как при необходимости очистить или перенести их.

## Корневой каталог данных

По умолчанию корневой каталог данных — `~/.multiai/`. Фактический путь зависит от платформы:

- macOS: `/Users/<name>/.multiai`
- Linux: `/home/<name>/.multiai`
- Windows: `C:\Users\<name>\.multiai`

Чтобы перенести каталог данных (например, изолировать конфигурации разных проектов с независимыми окружениями), задайте `MULTIAI_HOME`:

```sh
export MULTIAI_HOME="$HOME/.config/multiai"
```

После этого **все** данные MultiAI CLI — конфигурация, сеансы, журналы, учётные данные OAuth, пользовательские Skills для MultiAI, глобальный `AGENTS.md` и прочее — будут находиться по новому пути. Полное описание `MULTIAI_HOME` см. в разделе [Переменные окружения](./env-vars.md).

::: tip Примечание

**Универсальные ресурсы `.agents`** остаются в настоящем домашнем каталоге ОС, чтобы ими могли пользоваться разные инструменты. Например, универсальные пользовательские Skills остаются в `~/.agents/skills/`, а пользовательские Skills для MultiAI перемещаются вместе с `MULTIAI_HOME` в `$MULTIAI_HOME/skills/`.
:::

## Структура каталогов

```
$MULTIAI_HOME  (по умолчанию: ~/.multiai)
├── config.toml             # Пользовательская конфигурация
├── tui.toml                # Настройки терминального интерфейса (включая автообновление)
├── AGENTS.md               # Глобальные инструкции агента для MultiAI (необязательно)
├── mcp.json                # Пользовательские объявления серверов MCP (необязательно)
├── skills/                 # Пользовательские Skills для MultiAI (необязательно)
├── plugins/
│   ├── installed.json      # Записи об установленных плагинах и их состоянии
│   └── managed/            # Копии плагинов, установленных из zip/локальных путей
├── session_index.jsonl     # Индекс сеансов
├── credentials/            # Учётные данные OAuth (каталог 0700, файлы 0600)
│   ├── <name>.json
│   └── mcp/
│       └── <key>-<suffix>.json
├── sessions/               # Данные сеансов (см. ниже)
│   └── <workDirKey>/<sessionId>/
├── bin/
│   ├── rg                  # управляемый бинарный файл ripgrep для Grep (rg.exe в Windows)
│   └── fd                  # управляемый бинарный файл fd для ссылок на файлы (fd.exe в Windows)
├── logs/
│   └── multiai.log         # Глобальный диагностический журнал
├── updates/
│   ├── latest.json
│   ├── install.json
│   ├── install.lock
│   └── rollout.log
└── user-history/
    └── <md5(workDir)>.jsonl
```

## Описание файлов

У каждого файла верхнего уровня в корневом каталоге данных есть своё назначение; большинством из них CLI управляет автоматически:

- **`config.toml`**: основной файл рабочей конфигурации с пользовательскими настройками провайдеров, моделей и управления циклом. См. [Файлы конфигурации](./config-files.md).
- **`tui.toml`**: настройки клиента терминального интерфейса, включая `[upgrade].auto_install` (автообновление по умолчанию включено). Его можно отключить в `/settings` или вручную задать `auto_install = false`.
- **`AGENTS.md`**: глобальные инструкции агента для MultiAI. Файл перемещается вместе с `MULTIAI_HOME`; универсальные инструкции для разных инструментов можно хранить в `~/.agents/AGENTS.md`.
- **`mcp.json`**: пользовательские объявления серверов MCP, которые при запуске объединяются с локальным файлом проекта `.multiai/mcp.json`. См. [MCP](../customization/mcp.md).
- **`skills/`**: пользовательские Skills для MultiAI. Каталог перемещается вместе с `MULTIAI_HOME`; универсальные Skills можно хранить в `~/.agents/skills/`. См. [Agent Skills](../customization/skills.md).
- **`plugins/installed.json`**: записи об установленных плагинах, состоянии каждого плагина и изменениях состояния возможностей серверов MCP, внесённых через `/plugins` или `/plugins mcp disable|enable`. Файлы из локальных путей и URL zip копируются в `plugins/managed/<id>/`. См. [Плагины](../customization/plugins.md).
- **`credentials/`**: каталог учётных данных OAuth с правами `0o700` для каталога и `0o600` для файлов, доступный для чтения и записи только текущему пользователю. Учётные данные управляемых провайдеров хранятся в `credentials/<name>.json`, а серверов MCP — в `credentials/mcp/`. Для защиты от повреждения используется атомарная запись (tmp → fsync → rename).

## Данные сеансов

Данные каждого сеанса хранятся в `sessions/<workDirKey>/<sessionId>/`, а на верхнем уровне поддерживается индекс `session_index.jsonl` (одна запись в строке с полями `sessionId`, `sessionDir` и `workDir`). `workDirKey` — имя группы, полученное из пути рабочего каталога в формате `wd_<slug>_<first-12-chars-of-sha256>`.

В каждом каталоге сеанса находятся:

- **`state.json`**: метаданные сеанса, включая заголовок, `lastPrompt`, время создания и обновления, а также `forkedFrom`.
- **`upcoming-goals.json`**: очередь только для TUI, созданная командой `/goal next <objective>`. Она не входит в диалог агента, пока цель из очереди не станет текущей после завершения предыдущей.
- **`agents/main/wire.jsonl`**: полная запись обмена основного агента, используемая для возобновления и воспроизведения сеанса.
- **`agents/main/plans/`**: файлы планов из Plan mode, названные по идентификатору плана (`<id>.md`).
- **`agents/agent-0/` и т. д.**: каталоги экземпляров субагентов, каждый со своим `wire.jsonl`.
- **`logs/multiai.log`**: диагностический журнал этого сеанса; появляется только при диагностическом событии.
- **`tasks/`**: сохранённые фоновые задачи — в `tasks/<task_id>.json` хранятся состояние, PID и код завершения, а в `tasks/<task_id>/output.log` — вывод.
- **`cron/`**: сохранённые запланированные задачи; при возобновлении сеанса через `multiai --session` они повторно загружаются в планировщик. См. [Запланированные задачи](../reference/tools.md#scheduled-tasks).

## Кеш встроенных инструментов

Когда инструменту `Grep` впервые требуется ripgrep, CLI может автоматически скачать `rg` и сохранить его в `bin/rg` (`bin/rg.exe` в Windows). Для автодополнения ссылок на файлы терминальный интерфейс использует `fd`; при необходимости CLI в фоне скачивает его в `bin/fd` (`bin/fd.exe` в Windows). Последующие запуски используют кеш. `rg` сначала ищется в системном `PATH`, затем в кеше; `fd`, наоборот, сначала в управляемом кеше, затем среди системных `fd` / `fdfind`. После удаления `bin/` файлы будут скачаны заново при следующем использовании.

## Журналы и состояние обновлений

- **`logs/multiai.log`** (глобальный): записывает запуск, вход, экспорт и другие события между сеансами.
- **`<sessionDir>/logs/multiai.log`** (сеансовый): записывает диагностические события одного сеанса.

При сообщении об ошибке лучше экспортировать нужный сеанс через `multiai export` (см. [команду multiai](../reference/multiai-command.md)); журнал сеанса по умолчанию входит в экспорт. Добавьте `--no-include-global-log`, если не хотите передавать глобальный журнал.

Файлами в `updates/` (`latest.json`, `install.json`, `install.lock`, `rollout.log`) автоматически управляет механизм автообновления; обычно редактировать их не нужно. `rollout.log` фиксирует, какой вариант поэтапного развёртывания сработал при каждой проверке, и помогает понять, когда устройство получит новую версию.

## История ввода

История ввода терминала сохраняется отдельно для каждого рабочего каталога в `user-history/<md5(workDir)>.jsonl`. Она позволяет просматривать ранее введённые запросы клавишами со стрелками в терминальном интерфейсе.

## Очистка данных

Удаление корневого каталога данных (`~/.multiai/` или пути из `MULTIAI_HOME`) удаляет все рабочие данные. Чтобы очистить только часть данных:

| Цель | Действие |
| --- | --- |
| Сбросить конфигурацию | Удалить `~/.multiai/config.toml` |
| Сбросить настройки терминального интерфейса | Удалить `~/.multiai/tui.toml` |
| Очистить все сеансы | Удалить `~/.multiai/sessions/` и `session_index.jsonl` |
| Очистить диагностические журналы | Удалить `~/.multiai/logs/` |
| Очистить историю ввода | Удалить `~/.multiai/user-history/` |
| Сбросить состояние обновлений | Удалить `~/.multiai/updates/latest.json` |
| Принудительно скачать управляемые `rg` и `fd` заново | Удалить `~/.multiai/bin/` |
| Очистить состояние входа OAuth провайдера | Выполнить `/logout` или удалить соответствующий `credentials/<name>.json` |
| Очистить состояние входа OAuth сервера MCP | Удалить `credentials/mcp/` (`/logout` не очищает учётные данные MCP) |
| Удалить пользовательские объявления MCP | Удалить `$MULTIAI_HOME/mcp.json` (по умолчанию `~/.multiai/mcp.json`) |
| Очистить глобальные инструкции агента для MultiAI | Удалить `$MULTIAI_HOME/AGENTS.md` (по умолчанию `~/.multiai/AGENTS.md`) |
| Очистить записи об установке плагинов | Удалить `$MULTIAI_HOME/plugins/` (локальные исходные каталоги плагинов не изменятся) |
| Очистить пользовательские Skills для MultiAI | Удалить `$MULTIAI_HOME/skills/` (по умолчанию `~/.multiai/skills/`) |
